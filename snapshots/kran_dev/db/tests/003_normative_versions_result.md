# Нормативные источники и версии: результат прогона

**Дата:** 22.10.2026  
**Окружение:** PostgreSQL 16.15 + pgvector 0.8.7, новый изолированный auto-remove контейнер без общего/рабочего хранилища.  
**Схема:** `001_init.sql` → `002_seed_demo.sql` → `003_normative_source_versions.sql`.  
**Тест:** `db/tests/003_normative_versions.sql`.  
**Итог:** **PASS**, транзакция завершена `ROLLBACK`.

Проверено реальным SQL-поведением:

- две редакции одного нормативного источника с общей `source_series_id`;
- две версии коммерческого прайса с поставщиком, валютой и разными ценами;
- ровно одна рекомендуемая редакция в серии;
- поиск по коду, региону, типу и серии источника;
- расчёт `250 × 1000 × 1.1 / 100 = 2750.00` для расценки за 100 м²;
- формирование канонического `fixrate_rate_snapshot(rate_id)`;
- утверждение сметы со снимком цены 1000 RUB из редакции `2025.1`;
- изменение каталожной цены после утверждения не изменило `unit_price=1000` и `source_snapshot.base_price=1000` исторической позиции;
- новая редакция сохранила отдельную цену 1400 RUB;
- ручная позиция без `rate_id` принята только с описанием источника, автором, основанием, единицей, ценой и валютой;
- отклонены: цена без существующего источника, ручная цена без полного описания происхождения, подменённое поле канонического snapshot, активная ставка неподтверждённого норматива, подтверждённый DEMO-источник, вторая текущая редакция, несовместимый `price_basis`, несовместимая единица, повторное включение материала в итог, изменение утверждённой строки и удаление используемого источника.
