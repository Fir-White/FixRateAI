# Черновик Merge Request в develop

## Название

Подключить контракт прогноза и безопасный фотоанализ к backend/оркестратору

## Описание

Добавлен адаптер `ForecastSnapshot → ForecastResult(method=ai)` с проверкой принадлежности данных состояния снимку. Пока пригодная модель для данных заказчика не подтверждена, дата не выдаётся; демонстрационный RandomForest остаётся маркированным `synthetic_demo`.

Фотоанализ возвращает `unavailable` при недоступности CLIP, валидирует ответ модели и сохраняет ограничения для скрытых работ. Совпадение `view_key` не заменяет подтверждение человеком сопоставимости пары. Добавлены ограничение времени ожидания, воспроизводимые зависимости и сценарии отрицательных проверок.

## Проверка

- `python -m pytest ml_service/tests -q`: 34 passed в отдельном окружении Windows/Python 3.11.
- [Эксперимент OpenAI CLIP](clip_default_experiment.json) и [результаты сервиса](clip_service_experiment.json): четыре пары, в том числе несопоставимые фотографии; сырая модель реагирует на разные приборы и не выделяет изменение на фильтре. Это не метрика качества. Дополнительно проверен [TinyCLIP](clip_experiment.json).
- Сравнение с финальным `develop`, интеграционный тест с ALG/BE и миграциями: ожидаются.

## Условие создания MR

Создать MR только после появления `develop` и попадания в неё актуальных изменений БД и backend-контрактов; проверить итоговый diff и совместимость. Состояние `develop` нужно повторно проверить непосредственно перед созданием MR.
