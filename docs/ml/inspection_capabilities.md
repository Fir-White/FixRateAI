# Фотоанализ: возможности и проверка

| Случай | Текущий результат | Граница |
|---|---|---|
| Отсутствует CLIP или веса | `unavailable`, `MODEL_NOT_READY` | Эвристика не подменяет модель |
| Отсутствует пара, разное `view_key`, плохое качество | `uncertain` | Совпадающий `view_key` сам по себе не доказывает одинаковый ракурс или объект |
| Визуальный пункт при доступном CLIP | Сопоставление двух текстовых описаний чистой/грязной поверхности | Без `comparability_confirmed` сервис принудительно возвращает `uncertain`; порог и скоры не калиброваны |
| Скрытые операции, 1.5 и 1.6 | `not_verifiable` | Фото не подтверждает настройку, точность, внутренние детали или выпуск воздуха |
| Ошибка обработки | `failed` | Результат не является решением о приёмке |

Тестовые изображения в репозитории синтетические. [Эксперимент на четырёх парах из пользовательской папки](integration_validation.md) выполнен с основной моделью OpenAI CLIP и с отдельной компактной TinyCLIP. Происхождение фотографий и выполнение ТО независимо не подтверждены; модель ошибается на этих примерах, а количественное качество не оценено. Статусы не подтверждают выполнение работы; решение принимает контролёр. `review_photos` вызывается backend через `PhotoReviewRequest` и загрузчик байтов; реально подключённого backend-потока приёмки в текущей ветке нет.

Установка: `python -m pip install -r ml_service/requirements.txt -r ml_service/requirements-cv.txt`. Модель `openai/clip-vit-base-patch32` закреплена на ревизии `3d74acf9a28c67741b2f4f2ea7635f0aaf6f0268`; веса и процессор нужно предварительно скачать в локальный Hugging Face cache командой `python -c "from huggingface_hub import snapshot_download; snapshot_download('openai/clip-vit-base-patch32', revision='3d74acf9a28c67741b2f4f2ea7635f0aaf6f0268')"`. Инференс использует только локальный cache; без весов ответ `unavailable`. Вызов `ml_service.app.cv.api.invoke_review` ограничивает время ожидания backend, но не останавливает запущенный поток: production-провайдеру нужны отдельное ограничение ресурсов и отмена работы.

Для экспериментального прогона `python -m ml_service.inspect_pairs manifest.json results.json`: manifest — массив как минимум из двух объектов с полями `before`, `after` (пути относительно manifest), `source` (источник и разрешение), `comparable` (оценка человеком) и `visual_verifiability` (`visible` или `not_verifiable`). Сырые оценки CLIP фиксируются отдельно; ручная оценка несопоставимости или скрытого действия определяет ограниченный итоговый статус. Результат содержит SHA-256 файлов, версии, оценки и ограничения; оригиналы фото не копируются. Это не замена проверке сопоставимости человеком.
