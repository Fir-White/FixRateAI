# Материалы аналитика по ТО/ППР

Актуальные исполняемые правила ALG01/ALG02: [правила календаря](../algorithms/scheduling_rules.md)
и [контрактные примеры](../algorithms/examples.json). Прежние варианты в `pilot_regulations`
и `expected_schedule` сохранены с явным указанием расхождений; шаг 73 дня и перенос
выходных не включены в новый генератор.

Материалы из архива аналитика сохранены в исходном виде. Они описывают требования и примеры для пилота, а не подтверждают реализацию функциональности. Перед разработкой сверяйте их с [API-контрактами](../architecture/api_contracts.md), [границами прототипа](../architecture/prototype_scope.md) и [проектом базы данных](../database/README.md); различия в сущностях, статусах, ролях и правилах требуют согласования.

| Материал | Для чего использовать |
|---|---|
| [Пилотные регламенты](pilot_regulations.md) | Операции, периодичность, открытые вопросы к заказчику и допущения |
| [Пользовательские сценарии](user_flows.md) | Роли и права, жизненный цикл задачи и исключения |
| [Предметная модель и словарь данных](data_dictionary.md) | Сущности, связи, поля и бизнес-правила |
| [Ожидаемый график и тестовые сценарии](expected_schedule.md) | Примеры расчёта, позитивные и негативные сценарии |
| [JSON-примеры](examples/) | Операции, регламент, задача, связи с оборудованием и тестовые случаи |

Правила для квартального обслуживания и `5/год`, перенос выходных и квалификация исполнителей включают демонстрационные допущения. Год графика, даты обслуживания и смысл нормо-часов также требуют подтверждения заказчика; не используйте предположения для реальных назначений до согласования. Примеры и чек-листы аналитика необходимо проверять на соответствие согласованным контрактам и исходным данным.
