# Маршрутизация диалога FixRate AI

22.11.2026, MVP-11, PLN-12 и AT-08…AT-12. Каналы используют действующие роли и возможности объекта.

## Воспроизведение

На локальной версии до изменения отправили три сообщения без вложений. Объяснение RAG и черновик письма получили связный ответ, но каждый ход сохранён как цель `conversation` в плане. Запрос про `git diff`, аудит и тесты стал целью «Выбор модели чата для анализа кода и аудита репозитория». Трасса зафиксировала две попытки `chat_model_select`, чтение `chat_models` и `chat_model_preference`. Ответ завершился сообщением «Этот инструмент не принимает body». Карточек и изменений по этим трём запросам не было.

В исходном [оркестраторе](../../backend/app/assistant/orchestrator.py) состояние создавалось перед определением намерения. Обычный ответ был одним из видов цели, а `other` объединял текст, недоступные возможности и поддерживаемые предметные процессы вне словаря. При `other` выбор передавался общему планировщику. Тот видел весь каталог, хотя запрос мог вообще не относиться к системе. При отсутствии целей [построитель плана](../../backend/app/assistant/workflow.py) подставлял первые 400 символов запроса в заголовок. [Прежний промпт разговора](../../backend/app/assistant/prompts/conversation.md) отправлял вопросы вне продукта обратно к FixRate. Целевые проверки прежнего корпуса измеряли прежде всего чтения и подтверждения, поэтому объяснение и черновик внутри ненужного плана не выявлялись.

## Исполнение

[Классификатор](../../backend/app/assistant/dialogue_routing.py) возвращает семь типизированных видов ответа. Обычный разговор, справка по системе, уточнение и полностью недоступное действие завершаются обычным сохранённым ответом. Объяснение прежнего поручения получает сохранённые шаги и актуальные статусы доступных карточек. Историю ограничивают последние реплики того же авторизованного диалога.

Чтение, одна операция и многошаговая задача используют прежнюю семантическую привязку, выбор инструмента, доказательства, серверную подготовку, подтверждение и проверку результата. Инвентарный код или UUID с запросом на фактические поля сохраняют чтение при ошибочной классификации разговора. Результат классификации сам по себе не разрешает изменение. В маршруте чтения каталог оркестратора включает только разрешённые операции чтения. Смешанный ответ объясняет свежие результаты и указывает на явно запрошенную недоступную внешнюю возможность. Решение о доступе к данным остаётся у предметного API.

Панель «Состояние поручения» показывается для сохраняемых зависимых этапов. В обычных ответах и чтениях остаются ответ и история чата. Для одиночного изменения отдельная карточка по-прежнему показывает, что именно нужно подтвердить.

## Примеры

- «Что значит идемпотентный запрос?» → объяснение и пример повторной отправки без создания плана.
- «Посмотри мои задания и помоги написать короткое сообщение инженеру» → чтение доступных заданий с черновиком; отправка остаётся решением пользователя.
- «Начните работу по заданию, заполните чек-лист и отправьте отчёт инженеру» → сохранённый план, отдельная карточка начала, проверка фактов и подтверждение отправки.
- «Покажи git diff и запусти тесты» → пояснение про доступ из чата и предложение передать diff или вывод тестов.

[Запросы и критерии](dialogue-benchmark-20261122.json) зафиксированы до прогона. Каталог Git, терминала, внешней почты или произвольных сайтов не добавлялся. Сравнение предметных таблиц выполняется после каждого запроса. Карточка подготовки учитывается как запись журнала предложения.

## Результаты

| Проверка | Результат |
| --- | --- |
| Разговорный корпус через HTTP и PostgreSQL с локальной Qwen3.5 4B | 48/48 по техническим критериям после повторов. Экспортёр автоматически проверяет отдельные свойства содержания у D07 и D36 |
| Исходный корпус с теми же формулировками и критериями | Первый полный повтор 97/100. После точечной перепроверки 100/100 |
| Независимый корпус | Первый полный повтор 43/44. После точечной перепроверки 44/44 |
| Серверная регрессия | 117 прошли, включая 30 сценариев исполнения задания, RBAC, подтверждения и восстановление. Последняя выборочная проверка правил маршрутизации дала 7 успешных тестов |
| Интерфейс | Production-сборка, 40 тестов чата и Chrome на 1440 и 390 px |
| Изменения без подтверждения в разговорном корпусе | 0 |

В исходном корпусе повторили G02 после уточнения привязки рабочего электронного адреса к собственному профилю, G30 после восстановления состава задач фикстуры и E40 после возврата синтетического задания к состоянию до ранее подтверждённого начала. N21 повторили после сохранения явной ссылки на паспорт оборудования. Вердикт N21 подтверждает корректную границу источника. G39 и E40 подтвердили однократную запись и повтор без дополнительной мутации. Полные повторы и целевые проверки имеют отдельные результаты.

Экспортёр присваивает `quality=pass` по умолчанию. Поле `semantic` в машинной сводке отражает эту логику. Детали и поправка к прежней трактовке приведены в [аудите оркестратора](../architecture/assistant-orchestrator-audit-2026-11-22.md#23-как-читать-результаты-испытаний).

В Chrome открыли обычное объяснение RAG, ответ об ограничении Git, смешанный запрос о роли и тестах, вопрос о причине паузы, пятиэтапное поручение и чтение заданий с черновиком сообщения. Панель поручения появилась у пятиэтапного исполнения. Перезагрузка, Back/Forward, ввод и прокрутка проверены. Ошибок страницы и горизонтального переполнения в этих двух размерах не обнаружено.

Поддерживаемые внешние факты по-прежнему определяются каталогом и правами. Смешанный ответ о графике предлагает организационные варианты. Конкретное рабочее окно требует проверки доступности. Генеративные прогоны выполнены на локальной Ollama. Для AITunnel проверена общая интеграция маршрута в исходниках, отдельный живой корпус через него не запускался.
