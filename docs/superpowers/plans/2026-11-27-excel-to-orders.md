# Редактор таблицы ТО Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Главный инженер редактирует оперативную таблицу ТО в браузере, видит последствия перед записью и выгружает сохранённое состояние в XLSX.

**Architecture:** Отдельный режим в существующем «Планировании ТО», PostgreSQL — источник истины. Новые строки создают разовые неназначенные наряды по утверждённой привязке. Правки применяются после серверного предпросмотра и повторной проверки. Назначенный необработанный наряд переносится отдельно с прежней бригадой через штатный валидатор назначений.

**Tech Stack:** FastAPI/Pydantic, SQLAlchemy/PostgreSQL, React/Vite, существующий XLSX-экспорт.

**Spec:** Согласованный в диалоге сценарий «редактор → предпросмотр → подтверждение», отдельно — перенос назначенного. MVP-03/05/06/10/14; PLN-04/05/07/10/12/13/14. Обязательные сроки, утверждённый регламент и вводимые плановые трудозатраты — разные поля. Заказчик определяет действующие регламенты, состав/допуски и окно объекта; редактор их не выдумывает.

## Global Constraints

Без автозаписи на вводе, миграций, зависимостей, перезаписи исходной книги и изменения начатых/сданных/закрытых работ. Режим работает с оперативными нарядами; исходные версии опубликованных планов не изменяются. Существующие назначение, отчёт, инструкции и норматив нельзя подменять произвольным значением ячейки. Изоляция по объекту и роли, подтверждение и аудит на сервере.

## Review Focus

- Гонка с началом работы и изменением назначения после предпросмотра.
- Повтор HTTP после потери ответа, чужая ревизия и подмена запроса.
- Перенос назначенного на занятое окно или с частичным составом; отзыв доступа.
- Даты в местном времени, закрытые/исторические и опубликованные работы, неполный регламент.
- Неограниченный список, клавиатура, мобильный экран, выгрузка без исполняемых формул.
