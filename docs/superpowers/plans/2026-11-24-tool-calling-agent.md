# План единого агента FixRate AI

**Цель:** живой диалог инженера и исполнителя через штатный `/assistant`, без анализа формулировок программным кодом.

**Спецификация:** критерии этапов A–E из задания владельца. MVP-02/04/05 и TC: не подменять регламент нарядом и не предполагать рабочее окно, нормы или допуски.

1. **Цикл.** В `backend/app/assistant/tool_agent.py` реализовать `run` и ограниченный `run_loop`: нативный вызов провайдера, серверная диспетчеризация, результаты, ответ. Проверить передачу результатов, неизвестные инструменты, повтор, бюджет и изображения. В `service.py` подключить по версии исполнения; миграция сохраняет закрытый контекст отдельно от публичного workflow. Старые профили только явный откат.
2. **Предметные операции.** В `tool_agent_tools.py` предложить ограниченный каталог типизированных чтений и подготовку назначения. Подбирать исполнителей через штатную проверку, строить карточку по свежей команде backend. Проверить недоступность чужого наряда, изменение до подтверждения, сохранение ревизии и одно назначение при повторе.
3. **Фото.** Реальные байты текущего вложения и авторизованных снимков наряда; контекст работы и ограничения оценки передать модели. Проверить полезность ответа и отделение совета от приёмки.
4. **Интеграция.** Прогнать две роли через штатный API на новой PostgreSQL с Ollama; по возможности повторить через браузер. Отдельно сверить типы выходных данных, пустой/неполный ответ, отмену, отказ модели и диагностическую версию.
5. **Приёмка.** Новые формулировки и независимые ожидания SQL, протокол качества и задержек, четыре итоговых отчёта. Не считать заглушки показателем качества. Не трогать рабочие стенды и не наращивать облачный бюджет.
