# FX26-BE01: реализация API-контрактов

Дата: 27.10.2026. Статус: подготовлено для независимой разработки frontend, DB и ALG.

## Что добавлено

- Канонические DTO `maintenance-0.1` перенесены в
  [`backend/app/schemas/maintenance.py`](../../backend/app/schemas/maintenance.py).
- REST-модели находятся в
  [`backend/app/schemas/maintenance_api.py`](../../backend/app/schemas/maintenance_api.py):
  оборудование, операции, регламенты, периодичность, связи, календарь,
  плановые назначения, задания, фактические выполнения и роли.
- Три примера запросов/ответов находятся в
  [`backend/examples/maintenance_api_examples.json`](../../backend/examples/maintenance_api_examples.json).

## Правила

1. `schema_version` равен `maintenance-0.1`, неизвестные поля отклоняются.
2. `source_ref`, `data_origin`, вид ТО, периодичность, количество работников,
   исходная норма и её единица передаются явно.
3. Норма не преобразуется в минуты без подтверждённого `duration_basis`.
4. Календарь задаётся `year + month` и содержит массив событий `items`, а не
   31 отдельное поле дня.
5. Сервер генерирует идентификаторы; мутации используют `Idempotency-Key`,
   ревизионные команды — `expected_revision`; права проверяются на backend с
   учётом site scope.

## Ограничения

В репозитории до этой задачи отсутствовали зарегистрированные FastAPI endpoints,
repository и service-слой. Поэтому добавлены строгие DTO, но не фиктивное
хранилище и не success-заглушки. Следующий этап — подключение моделей к сервисам
и генерация OpenAPI из реального приложения.

До подтверждения заказчиком года, дат квартального и годового ТО и единицы нормы
нельзя создавать реальные назначения или записывать выполнение.
