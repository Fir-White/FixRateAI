## Сопоставление с прежним корпусом

Корпус 60/60 шёл через реальный FastAPI, PostgreSQL и тот же драйвер графа. Управляемые ответы планировщика в нём задавали нужные предметные намерения. Он обнаруживал ошибки источников, разрешений и проверок результатов, но не воспроизводил длинные формулировки №2, №3, №5 и №6 в одном диалоге. Короткие проверки переключения контекста охватывали упрощённый синтаксис. Новый тест проводит пять дословных реплик одной HTTP-сессией, с проверкой Registry, узла проверки, выбранного UUID, SQL-счётчиков, нескольких страниц и неизменности предметных таблиц. В профиле локальной Qwen №1 проходит через реально вызванную модель. №2, №3, №5 и №6 используют детерминированные маршруты с нулём LLM-вызовов. [E2E-проверки](../../tests/backend/test_assistant_user_audit_v3.py)

## Воспроизведение и ограничения

`scripts/verify.py --agent-only --pytest-target tests/backend/test_assistant_user_audit_v3.py` разворачивает временную PostgreSQL. Отдельный прогон выполняет `scripts/verify_agent_local.py --live --model qwen3.5:4b-q4_K_M --pytest-target tests/backend/test_assistant_user_audit_v3.py`. Тест проверяет фактический вызов закреплённой Qwen для №1 и нулевое число вызовов модели для четырёх точных аналитических маршрутов. До изменений локальные исходные трассы сохранены в `var/agent-v3-user-audit-20261123/before.json`. Предметные данные этого протокола остаются в приватной рабочей папке.

Срез на прошедшую дату сопоставляет нормативные сроки с датой по состояниям текущего реестра. История состояний заданий и подлинный состав публикаций регламентов на прошедшую дату источниками не подтверждаются. Для назначений свыше предела сохранённого снимка ответ явно указывает покрытие доступной части.
