# Архитектурные сценарии и проверка 26.10.2026

Исторический срез: 26.10.2026. Текущие правила (включая yearly_count и общий CalendarPattern) описаны в [календаре](../service/calendar.md), фактические прогоны — в [индексе проверок](../verification/INDEX.md). Метод: сопоставление требований с потоками данных, статусами, версиями, транзакциями и поведением при отказах. Матрица ниже — **архитектурный разбор**, а не протокол выполненных интеграционных тестов приложения.

Источники правил: [архитектура](system_architecture.md), [модель](../service/data.md), [контракты](../service/api.md), [проверка Excel](../service/domain.md). Для всех сценариев предусмотрена неизменяемая история и аудит; возможный результат `needs_input` считается корректным контролируемым отказом, а не вычисленной датой.

## Дополнительные проверки перед демонстрацией

Проверить права каждой роли и site scope, запрет собственной приёмки, обязательные CSRF/revision/idempotency, повтор upload/submit/review, неверные единицы и naive timestamps, чужой snapshot, отсутствующий storage, недоступную БД, двойное назначение и двойную приёмку. Прогноз по runtime отдельно проверяет единицы `hours`, сброс счётчика и отсутствие даты при неизвестном режиме наработки.

Статистическая проверка AI — отдельная от контрактной: зафиксировать train/test границы по времени и оборудованию, target, seed, размер выборки, MAE/опоздания, происхождение и отсутствие утечки. Контрактно валидный прогноз не доказывает предсказательной полезности. CLIP нужно прогнать на сопоставимых реальных тестовых фото и на плохих/непроверяемых примерах; числа сходства не превращаются в промышленную оценку качества ТО.

## Фактически выполненная проверка этого комплекта

Команда из корня репозитория:

```powershell
python -B docs/architecture/validate_artifacts.py
```

Проверяются десериализация JSON-примеров, общий контекст прогнозов, допустимость выбранной даты, ссылки заданий/попытки/фото/решения, комплектность демонстрационной бригады, совпадение экспортированной схемы с DTO, отрицательные примеры, локальные Markdown-ссылки, XML и рёбра draw.io относительно Mermaid, совпадение Mermaid-источника с документом, наличие всех 15 строк сценариев. Это проверка артефактов на подготовленных примерах, не исполнение будущей бизнес-логики.

Исходный Excel прочитан и сверены значения/координаты, 93 отметки, отсутствие дат ТО2, формул/скрытых данных; его SHA-256 зафиксирован в анализе. Git проверен read-only: пустой HEAD main и архивные снимки подтверждены, переключения/commit/push не выполнялись.

Новые интеграционные/API/SQL/frontend тесты, обучение RandomForest, inference CLIP, запуск Compose и измерения производительности **не выполнялись**: runtime-код ТО/ППР отсутствует и не входит в эту архитектурную задачу. Исторические результаты сметного проекта не зачтены. Окончательное число фактически проверенных JSON/ссылок фиксируется выводом команды; при изменении документации команду следует повторить.

Фактический локальный прогон 26.10.2026: Windows, Python 3.11.9, Pydantic 2.14.0. Экспорт JSON Schema создан этой версией Pydantic; при смене генератора возможна необходимость согласованного переэкспорта через `--write-schema`.

## Вывод проектной проверки

Все 15 сценариев имеют определённые входы, допустимый результат либо контролируемый отказ и место хранения решения. Архитектурных противоречий, требующих изменения выбранных границ модулей, по разбору сценариев не осталось. Открытые нормативные вопросы и недостаток данных AI перечислены в анализе Excel и ограничивают утверждение реального графика/оценку качества, а не скрываются успешной проверкой JSON.

Архитектурное проектирование как подготовку инженерного фундамента на 26.10.2026 можно считать выполненным после успешной локальной проверки комплекта. Согласование с заказчиком, окончательная БД и реализационная готовность к 07.11 остаются отдельными этапами.
