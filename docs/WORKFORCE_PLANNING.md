# Настройка оборудования и работников

Текущий dev, SQL 001–008. Это действующий процесс планирования обслуживания, а не архивный оценщик повреждений по фото.

1. Администратор в `/settings/workforce` создаёт код компании. Работник регистрируется через `/register`: имя, email, пароль, код. Заявка ожидает решения, роль клиент не выбирает. До выдачи активного членства вход в рабочую область запрещён.
2. Администратор назначает одну роль в объекте и даты трудоустройства. Диспетчер/администратор задаёт допуски, повторяющиеся смены, исключения доступности и датированный состав бригад. Последнего администратора нельзя снять. Инженер читает настройки, исполнитель видит только собственные смены в `/my-shifts`.
3. В `/settings/equipment` администратор/диспетчер создаёт оборудование и версионированную конфигурацию обслуживания: период, дату действия, численность, норму с единицей, отдельную длительность, допуски и чек-лист. Можно применить имеющуюся операцию к другому оборудованию. Типы ответов чек-листа: boolean/number/text, единицы, обязательность, фото и визуальная проверяемость сохраняются отдельно.
4. Общий CalendarPattern описывает обслуживание и смены: интервалы дней/недель/месяцев/кварталов/лет, ISO-чётность, дни недели, сезоны, годовое число, выбранные даты и исключения. В редакторе доступен серверный предпросмотр дат. Ночные смены переходят на следующий день; несуществующее/неоднозначное местное время закрывается диагностикой.
5. Диспетчер получает предпросмотр календаря, затем отдельной командой создаёт задания. Система показывает подходящих работников и бригады, приоритет и причины исключений. Можно выбрать постоянную бригаду либо отдельных работников, включая участников бригад. Выбранный вручную состав обязательно проходит повторный расчёт; незаметная подмена работников запрещена.
6. «Подтвердить назначение» заново проверяет ревизию, активность, даты занятости, смены, исключения, допуски на весь интервал и бронирования во всех объектах. Только успешная транзакция сохраняет состав и аудит. Подбор/предпросмотр/AI ничего не назначают автоматически.

Смена — время работы человека. Бригада — датированный набор людей. Назначение — отдельная бронь конкретного задания; ни членство в бригаде, ни смена сами по себе не создают бронь.

Отсутствие доступности означает отсутствие разрешённого интервала. Недоступность вычитается из суммы смен и дополнительных доступных окон, затем интервалы ограничиваются датами трудоустройства. Непроверенный/истёкший допуск не подходит. Неизвестные критические факты дают needs_input, а не разрешение.

Изменения смен/допусков/состава/трудоустройства не могут сделать уже подтверждённую будущую работу недопустимой: сервер отклоняет конфликт 409, сохраняя прежние данные. Допуск отзывается с ревизией и аудитом. Для замены будущей работы диспетчер может отменить задание до начала и без отчёта, указав причину; бронь освобождается, история остаётся.

Правки обслуживания создают новую версию и закрывают предыдущую привязку. Существующие наряды и чек-листы используют замороженные снимки. При конфликте с уже созданной будущей работой нужно сначала разрешить её явно; новая настройка не переписывает историю.

Действующие маршруты: [API](architecture/api_contracts.md), физическое соответствие: [DTO/SQL](architecture/dto_db_mapping.md), календарь: [ALG01/02](algorithms/scheduling_rules.md), назначение: [ALG03](algorithms/assignment_rules.md) и [BE05](algorithms/assignment_persistence.md). Требуется миграция 008; приложение не применяет SQL при запуске.

Границы: нет автоматического составления оптимального штатного расписания, формального утверждения месяца, повторного открытия принятого отчёта, автономного назначения и обучения RF на неизвестных данных заказчика. Календарь собственных смен показывает рабочие интервалы/исключения; конкретные работы остаются в кабинете исполнителя. Сессия выбирает один объект и одну роль.
