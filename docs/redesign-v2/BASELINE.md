Для четырёх anchor есть 1440×900 и 390×844. У реестров management снят заполненный mobile `/tasks`. Имеется 173 уникальных кадра. Два старых кадра chief с Y98/Y493 отмечены как форма оборудования до выбора, а не редактор обслуживания.

## Наблюдаемые исходные проблемы

- Связь оборудования показывает «Не указано» у реальных заданий; причина требует C17, по PNG её не устанавливаем.
- Инженер: документы и история предшествуют h1, решение на mobile находится около Y6900, после длинного AI-разбора.
- Chief: существующий редактор открывается, но длинная mobile форма достигает около 9348 px; действия сохранения находятся внизу. Это не тест сохранения.
- Director: экспортная сводка расположена перед названием страницы. AI честно показывает отсутствие результата из-за недостатка истории.
- Исполнитель: текущая попытка и история видны, сохранённые ответы требуют проверки read-only представления.

## Карта запуска и проверки

Frontend: React 19, TypeScript, Vite. Команды из `frontend`: `npm run typecheck`, `npm run build`, `npm test`; отдельного lint script нет. Браузерные тесты: `npm run test:e2e`, конфигурация `frontend/playwright.config.ts`, реальные и изолированные transport fixtures в `tests/web/e2e`.

На машине установлен PostgreSQL 18. Существующий `scripts/verify.py` создаёт отдельный loopback кластер во временном каталоге, самостоятельные БД и случайный пароль; `DATABASE_URL` рабочего проекта не читает, cloud AI ключи очищает. Для полной проверки из worktree:

```powershell
& 'D:/FixRate AI/FixRate_AI/.venv/Scripts/python.exe' scripts/verify.py --pg-bin 'C:/Program Files/PostgreSQL/18/bin' --browser
```

Наличие runner и PostgreSQL — подтверждённая возможность, а не уже пройденный C16. Артефакты запусков согласно [правилам разработки](../service/development.md) остаются в `reports`, журналы — в `logs`.

### Изолированный Docker runtime для текущего прогона

При подготовке обнаружена несовместимость локальных Python: 3.11 не разбирает существующий PEP 701 код; установленный 3.14 не содержит backend-зависимостей. Поэтому подготовлен отдельный Docker runtime на существующем `fixrate-ai:notice-copy`, с read-only bind исходников worktree, новым PostgreSQL 18 в tmpfs и новым seed. API `http://127.0.0.1:18074/api/health` вернул `status=ok`, `database=ready`. Рабочий `:8000` не изменён.

Скрипты: `scripts/redesign_qa_start.ps1`, `scripts/redesign_qa_api.py`, `scripts/redesign_qa_browser.ps1`. Случайный тестовый пароль хранится только в игнорируемом `var/redesign-v2/qa-state.json` и не выводится. PostgreSQL подключён исключительно к внутренней сети `fixrate-redesign-qa`; API дополнительно подключён к отдельной bridge-сети `fixrate-redesign-qa-browser`, необходимой для публикации loopback-порта Docker. Cloud AI ключи очищены. Фото сохраняются только внутри тестового API-контейнера.

Перед окончательной browser-регрессией нужно собрать актуальный frontend. Контейнер читает `frontend/dist` из worktree; обновление исходников backend требует перезапуска только `fixrate-redesign-qa-api`. Затем запустить `powershell -File scripts/redesign_qa_browser.ps1`. Наличие healthy окружения не считается успешным C16. После завершения удалить только контейнеры `fixrate-redesign-qa-api`, `fixrate-redesign-qa-db` и созданные для них две сети; основного `fixrate-local` это не касается.

Маршруты и разрешения задаются `frontend/src/app/router.tsx`, `shared/lib/roles.ts` и сервером. `WorkspaceNavigation`, sidebar, topbar, профиль и уведомления исключены из редизайна. `AppShell` содержит общий `<main>` и `<Outlet>`; тематическая область должна исключать `/profile` и не распространяться на topbar/overlay уведомлений.
