## Локальный запуск и безопасный возврат

Открыть `.worktrees/frontend-redesign-v2`. С установленными зависимостями из `frontend` выполнить `$env:VITE_DEMO_MODE='false'; npm.cmd run dev -- --host 127.0.0.1 --port 5174`. Vite использует существующий API proxy :8000. Это просмотр новой ветки поверх существующих данных, а не автоматическое развёртывание. Изолированные mutating проверки запускаются только через QA scripts, описанные в [REGRESSION](REGRESSION.md).

Возврат к стабильной версии не требует reset или удаления worktree: остановить только новый Vite и открыть прежний работающий :8000 либо исходное дерево `frontend_polished`. Read-only проверка прежнего `/api/health` после изменений вернула `status=ok,database=ready`; исходное дерево было чистым при baseline, merge-base совпал с исходным SHA; текущее пользовательское изменение docs/service/runtime.md в исходном checkout сохранено. Для самостоятельной сборки старой версии использовать отдельный worktree от SHA `422eacf94aadf0fc75e29ef8b1ee110abce78bd2`. Не сбрасывать текущие незакоммиченные файлы, не восстанавливать старую БД поверх новых бизнес-событий. Код не требует новой миграции; пользовательские приёмки, фото и история кодовым откатом не отменяются.

Перед демонстрацией нужна ручная приёмка оставшихся обязательных сценариев доступности и подтверждение нормативов customer-объекта. Presentation-связи оборудования восстановлены; это не подтверждает нормативы заказчика. Старый стенд остаётся доступен. Учётные данные берутся только из приватного var/compose-local/accounts.txt; в документацию и Git пароли не копируются.
