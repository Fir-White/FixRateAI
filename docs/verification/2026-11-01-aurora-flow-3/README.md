# Organic Aurora Flow 3.0 — проверка 01.11.2026

Проверена текущая `feature/frontend-kran`, HEAD `2948458` с незакоммиченными изменениями. Baseline снят с фактического рабочего дерева до этой задачи, а не с чистого HEAD. Существовавшие изменения сохранены; Git commit/push/merge/rebase/reset и переключения веток не выполнялись.

## Итоговая реализация

Две существующие световые ленты сохраняют исходную композицию и неподвижные концы. Каждый внутренний участок получает собственную детерминированную последовательность направлений и расстояний изгиба. Quintic-интерполяция и независимые медленные компоненты обеспечивают непрерывность без короткого повторяющегося маршрута. После уточнений пользователя базовые интервалы 8/8,9 с ускорены ровно в 1,3 раза: около 6,15/6,85 с с небольшим индивидуальным разбросом участков.

Сохранён SVG renderer: два общих пути для внешнего glow, цветного тела и ядра обновляются максимум 30 раз/с. Один rAF обслуживает геометрию и существующие частицы; React state, DOM measurements и поиск элементов внутри кадров отсутствуют. Весь Aurora pointer pipeline удалён. Логотип, его SVG, статичный ambient, композиция и логика авторизации не изменялись этой задачей. Новые библиотеки и декоративные системы не добавлялись.

Единственный автор изменений исходников — React Engineer; Motion Designer и Visual QA проверяли независимо. Design Director принял геометрию и композицию по их отчётам и кадрам браузера. Это техническая приёмка в локальной среде, не утверждение об измерении на всех офисных компьютерах.

## Производительность до и после

Windows, Node 24.21.0, Chrome 156.0.8078.79 headless, DPR 1, Vite на `127.0.0.1:5174`. API-сессия локально подменялась ответом 401; frontend-модули продолжали загружаться с Vite. Замер включает rAF callback duration, интервалы отдельного rAF-наблюдателя и CDP Performance metrics. Native rAF в этой среде около 144 Гц. Интервалы rAF не являются измерением фактически показанного FPS или GPU raster time.

| Сценарий | p95 callback до → после, мс | p95 rAF до → после, мс | Максимальный rAF до → после, мс | rAF >25 мс до → после |
|---|---|---|---|---|
| 1440×900, 30 с | 0,4 → 0,4 | 7,1 → 7,1 | 14,0 → 13,9 | 0 → 0 |
| 1920×1080, 12 с | 0,3 → 0,4 | 7,1 → 7,1 | 7,3 → 14,0 | 0 → 0 |
| 1440×900, CPU ×4, 12 с | 1,2 → 2,1 | 7,1 → 7,1 | 13,8 → 41,7 | 0 → 2 |

Сырые результаты: [baseline](baseline-performance.json), [финал ×1,3](final-performance.json). Средняя доля времени main thread по CDP TaskDuration выросла примерно с 9,8% до 12,6% на 1440×900, с 8,1% до 12,1% на 1920×1080 и с 31,7% до 62,3% при искусственном CPU ×4. Частота обновления геометрии изменилась с 24 до 30 Гц; измеренная стоимость выросла, ускорение производительности не заявляется.

Из-за двух выбросов повторён только CPU ×4 сценарий отдельно на 30 с: p95 callback 1,8 мс, p95 rAF 7,1 мс, максимум 69,6 мс, два интервала >25 мс, один >50 мс — [повторный замер](stress-repeat-performance.json). В независимом browser review с чтением пикселей и screenshots максимум 27,8 мс, один интервал >25 мс, long tasks не зарегистрированы. Редкие задержки под искусственной нагрузкой остаются ограничением; стабильные 60 FPS на любом устройстве не заявляются.

В обычном измеренном режиме SVG сохранил плавный scheduler cadence и синхронное свечение; этого достаточно для сохранения текущего renderer без новой Canvas/WebGL реализации. Если целевой компьютер показывает рывки, следующий шаг — профилирование paint/raster и кэширование, затем сравнение Canvas на том же устройстве. Стресс-замеры сохранены полностью.
