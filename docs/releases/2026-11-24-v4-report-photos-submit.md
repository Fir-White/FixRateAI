# Фото и сдача отчёта из чата v4

Исполнитель может вставить снимки из буфера в новый или открытый чат, сверить их по миниатюрам и явно отправить. Существующие файлы переписки доступны после обновления без повторной загрузки. Снимки из наряда, прочитанные ассистентом после этой итерации, открываются в том же чате, но помечены как фото из отчёта. XLSX по-прежнему скачивается. Над перепиской остаётся один компактный ряд навигации по чату, основная шапка приложения не изменена.

Нативный инструмент v4 готовит карточку для автора текущей попытки. Одно подтверждение прикрепляет до четырёх отправленных снимков к указанным пунктам. При полном комплекте отчёт переходит в очередь инженера; иначе он остаётся черновиком, а карточка сообщает недостающие данные. Показания, фактические поля, ответы чек-листа и решения о приёмке команда не меняет.

## Контракт и эксплуатация

- `report_attach_and_submit`: ревизия наряда, идентификатор попытки и привязки файла к пункту, фазе и ракурсу. Команда доступна только в нативном диалоге v4; из общего чата нужно указать один точный код наряда или открыть чат из его карточки. Если в текущем сообщении два фото с однозначными метками `before`/`after` или `до`/`после` и в отчёте один пункт с обязательными фото, карточка может предложить эту привязку. При простой команде в чате наряда для этого не нужен вызов модели. Явные фазы пользователя имеют приоритет; для неоднозначной пары укажите пункт, фазы по номерам и ракурс. Уточнение без повторной загрузки может использовать явно выбранные снимки непосредственно предыдущего сообщения.
- Без подтверждённой карточки запись недоступна. При подтверждении заново проверяются права, состояние наряда, принадлежность и целостность файлов. На время записи удерживаются блокировки наряда и действующего контекста доступа. Повторное подтверждение не запускает запись снова. Штатный фотоанализ при сдаче не задерживает ответ на подтверждение.
- Договорённость о составе отчёта и проверка качества снимков остаются предметными; конвертации полей отчёта из ответа модели нет. Просмотр повторно использует защищённые маршруты изображений.
- Новых зависимостей и миграций нет. Для отката локального стенда достаточно вернуть предыдущий пакет API/SPA, сохранив БД и хранилище; резервный снимок перед переключением не требует остановки PostgreSQL.
