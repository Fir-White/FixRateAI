# ИИ-агент v4 — локальная контрольная точка, 24.11.2026

MVP‑11 (чат), MVP‑08 (наряды и назначение), MVP‑07 (доказательства) и MVP‑04 (календарь); PLN‑12, AT‑08…AT‑12, AN06. Этот срез фиксирует новый маршрут и границы приёмки, а не готовность к пилоту. Для реального объекта нужны подтверждённые регламенты, плановые даты, смены и допуски.

Основной dev-профиль теперь `v4`: модель выбирает инструменты, сервер проверяет данные и авторизацию. Наряды, календарные события и расчётные даты не взаимозаменяемы. Исполнитель открывает чат из своего наряда и может отправить снимок на предварительную оценку без изменений отчёта и без автоматической приёмки. Миграция 029 дополняет схему, не переписывает историю; `v2` и `v3` доступны по явной настройке отката.

### Подтверждение назначения

После расчёта состава короткий выбор полного состава может завершаться существующим серверным предложением `task_assign`. Реплика «подтверждаю» не выполняет назначения. Инженер должен сверить наряд и состав в реальной карточке и нажать «Подтвердить и выполнить». Для того же наряда, окна, ревизии и состава повторно используется действующая карточка; чужая, истёкшая или устаревшая не разрешает запись.

В изолированной PostgreSQL прошли 75 серверных проверок. В Chrome на локальной Qwen 8K прошли три сквозных сценария, включая исходное продолжение подбора с двумя людьми и последующий клик подтверждения. Профиль из замера не заменяет независимый корпус.

### Сводка нарядов и локальная дата

Поиск без фильтров в v4 читает общий счётчик, все восемь статусов и отдельный счётчик на текущий день. Параметр `summary_on` реестра включает агрегацию на PostgreSQL до пагинации, в пределах той же области прав. Существующие вызовы без параметра сохраняют прежний ответ. Относительные даты разрешаются на сервере в зоне объекта на момент начала реплики. `FIXRATE_DEFAULT_TIMEZONE=Asia/Yekaterinburg` используется при создании первого объекта, уже настроенные зоны не меняются. Источник времени — системные часы хоста, а не дата наряда или вызов внешнего сервиса. Для этого изменения новые миграции не нужны.

Локальный API может выбирать DeepSeek для чата через защищённый `.env`: `ASSISTANT_PROVIDER=aitunnel`, `AITUNNEL_CHAT_MODEL=deepseek-v4-flash` и приватный `AITUNNEL_API_KEY`. Настройки фотоанализа отдельные. На локальном стенде были проверены загрузка настройки сервером и доступность модели в каталоге, затем вручную выполнено три диалога с облачным провайдером. Содержимое БД стенда, книга, рабочий ключ, фотографии прогона и частные протоколы в Git не входят.

Живой прогон инженера по независимым SQL-счётчикам: T01 (общая аналитика) — частично, T02 (просрок и риск) — не пройден, T03 (ближайшее и следующее ТО) — пройден с замечаниями. Общий счётчик и текущий день совпали с реестром, порядок двух соседних нарядов сохранён. Карточек действий в этих диалогах не создавалось. Модель несколько раз смешала прошедшее плановое окно и обязательный срок; точное время срока не было передано в поисковой выдаче по дням. Не подтверждены рекомендации о риске без проверки бригады и отдельная повторная сверка после возражения пользователя. Три диалога не доказывают целевые проценты, p95, качество фото или облачное назначение.
