# FixRate AI Agent v3 на LangGraph

Реализация в ветке разработки. Исходный срез сравнения — `f519c3bae8d98992bcf6164bcd29577b3c967a88`. [Аудит, состояние, схема исполнения и RBAC](../architecture/assistant-architecture-v3.md).

## Запуск и откат

Порядок для локальной установки после обновления Python-зависимостей.

```powershell
python -m pip install -r requirements.txt
$env:PYTHONPATH = 'backend;.'
python -m app.manage migrate
$env:FIXRATE_ASSISTANT_AGENT_VERSION = 'v3'
python -m uvicorn app.main:app --app-dir backend --host 127.0.0.1 --port 8000
```

Команда миграции использует настроенное подключение к БД. Миграция 028 сохраняет историю существующих диалогов и помечает имеющиеся сообщения как v2. Для Compose переменная задаётся в конфигурации установки. Откат выполняется изменением значения на `v2` и перезапуском API для новых поручений. Ранее созданные поручения и их карточки действий обслуживаются сохранённой версией. Для включения v3 пользователь выбирает ту же модель чата и работает через существующие «Остановить», «Продолжить» и «Подтвердить». Применение к рабочей БД и развёртывание в этот срез не входят.

На изолированной PostgreSQL применили 027, создали диалог с завершённым сообщением и дважды запустили миграцию текущего кода. Проверены сохранность сообщения, автора, роли, ключа запроса и ответа, назначение версии v2 существующей записи и идемпотентность миграций поставщика checkpoint.

## Проверки

Команды с `scripts/verify.py --agent-only` разворачивают новую локальную PostgreSQL, применяют миграции и восстанавливают демонабор. Для сравнения версии задаются отдельно через `FIXRATE_ASSISTANT_AGENT_VERSION`. Именованные наборы включают `test_assistant_graph_v3.py`, `test_assistant_dependent_analytics.py`, `test_assistant_runtime_dataflow.py` и `test_assistant_v2_benchmark.py`.

Повтор после исправлений дал **125 passed** на PostgreSQL 18.6. В него входят шесть опорных сценариев, проверки чекпойнтов, составного изменения, вложений, разрешений и снимков. На окончательном коде профиль графа дополнительно дал **6 passed**, режим отката v2 — **29 passed**. Два сценария восстановления проверяют продолжение узла после прерывания и подтверждение после пересоздания приложения с v2 для новых поручений. В проверку входят попытка из чужой сессии и повторное подтверждение.

На исходном SHA полный backend-прогон дал **2864 passed, 64 skipped, 1 xfailed** и один отказ из-за отсутствия Compose-файла в архиве. После добавления того же файла из исходного SHA этот тест прошёл отдельно. Ранний полный v3-прогон дал **2859 passed, 10 failed, 64 skipped, 1 xfailed**. Все десять отказов относятся к проверенным в повторе из 125 тестов. После исправлений полного повторного прогона всего backend не было. Сырые журналы находятся в `logs/verification/agent-v3-regression/` и `logs/verification/agent-v3-recheck/`.

Контрольный корпус сравнивался на одинаковых фабриках данных с управляемыми ответами модели и реальными HTTP/PostgreSQL. Показатели задержки измерены от отправки до завершения проверки сценария. Отрицательные сценарии проходят, когда сервер возвращает предусмотренное ограничение.

| Метрика | Исходный v2 | v3 |
| --- | ---: | ---: |
| Сценарии, прошедшие независимые критерии | 60 / 60 | 60 / 60 |
| Проверенные утверждения | 293 / 293 | 293 / 293 |
| Разрешение UUID на этапе предметного вызова | 66 / 66 | 66 / 66 |
| Вызовы чтения и подготовки | 129 | 129 |
| Успешные чтения и предложения | 126 / 129 | 126 / 129 |
| Вызовы модели | 118 | 118 |
| Время p50 / p95, с | 0,245 / 0,459 | 0,272 / 0,543 |

Три ошибки чтения в каждом контуре были предусмотрены сценарием. Корпус подтвердил два случая однократной записи и один случай повторного чтения незавершённого этапа в каждой версии. Точное сравнение, выбор победителя по доказательствам и восстановление checkpoint проверены отдельными тестами v3. На общем корпусе качество сохранилось, а измеренная задержка v3 выше. Широкая точность свободных ответов по этим 60 сценариям не измеряется.

В обоих запусках на реальной локальной `qwen3.5:4b-q4_K_M` составной запрос НС‑01 закрыл все семь требований. В каждом запуске было 4 вызова модели и 6 учтённых операций с данными. На v2 запрос занял 26,22 с, использовал 4291 входной и 720 выходных токенов. На v3 запрос занял 47,93 с, использовал 4291 входной и 741 выходной токен. Одиночные замеры прошли при разной нагрузке на модель и не устанавливают относительную скорость контуров.

В Chrome прошли два сценария с реальным API и тестовой БД. Главный инженер нашёл точную карточку, исполнитель получил свои сегодняшние задания. Проверены исход в графе, ноль генеративных вызовов и восстановление диалога после перезагрузки на 1440 и 390 px. Дополнительно прошли 19 проверок production-сборки с подменой ответов API. Они охватили историю, длинную переписку, ввод, нативную прокрутку, вложения и reduced motion. Четыре сценария специального QA-стенда были пропущены. Linux/amd64 lock разрешился для Python 3.12, локальные проверки `pip check`, схем и 181 операции ассистента прошли.

В production Chrome на 1440, 390 и 320 px задержка ввода p95 до второго `requestAnimationFrame` составила 14,0–14,7 мс при CPU ×1 и 14,4–16,3 мс при CPU ×4. Интервал кадров p95 при нативной прокрутке составил 7,0–7,1 мс. В этих выборках длинных задач не зарегистрировано.

## Готовность

Версия v3 доступна по флагу для пилотного развёртывания. Для промышленной приёмки остаются расширенные проверки формулировок на реальной модели, нагрузочные испытания и проверка совместной работы нескольких процессов API. Полное покрытие 739 сочетаний ролей и операций оценивается отдельной матрицей. Диагностика исторических запросов ограничена источниками состояния на заданную дату.
