# Общая база dev из kran_dev — 17.11.2026

## Решение и границы

По запросу владельца в `dev` объединяются опубликованный срез `kran_dev` и существующая командная работа. Это интеграционная база для дальнейшей разработки. Известные дефекты и невыполненные требования сохраняют открытый статус; объединение не означает готовность MVP, принятие ML-результатов или production-развёртывание.

Используется обычный merge с двумя родителями, без переписывания истории и без замены дерева dev целиком. Состав входящего среза, реализованные сценарии, миграции 022–024 и ограничения подробно описаны в [отчёте публикации kran_dev](2026-11-17-kran-dev-publication.md). Его машинная опись относится именно к тому срезу, а не к дополнительным ML-файлам этого объединения. Новые runtime-контракты и миграции непосредственно при разрешении merge не добавляются.

## Как команде наследовать базу

Новые рабочие ветки создаются от актуального `origin/dev`. Существующие личные ветки автоматически не обновляются: каждый сохраняет свои изменения коммитом, выполняет `git fetch origin`, затем объединяет `origin/dev` в свою ветку и разрешает собственные конфликты. Перезаписывать личные ветки и применять force push для этого не требуется.

`main`, production и пользовательские настройки этим merge не меняются. GitHub push является отдельным шагом после локального merge-коммита; возможное последующее зеркалирование штатной автоматикой не считается проверенным фактом без отдельного чтения удалённых refs. План редизайна приостановлен до завершения сохранения общей базы.
