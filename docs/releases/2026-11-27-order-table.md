# Оперативная таблица нарядов ТО — 27.11.2026

Исходный срез подготовлен в ветке `feature/excel-to-orders-20261127` от `ea97765` и включён в [демонстрационный кандидат](2026-11-27-release-readiness.md). До начала итерации `origin/dev` указывал на `a8c9037`; изменения фотоанализа между ним и `ea97765` описаны [отдельно](2026-11-26-aitunnel-photo-review.md), а в diff редактора не входят. Проверки относятся к учебным данным, а не к развёртыванию.

## Что изменилось

- **Главный инженер → Планирование ТО → Таблица нарядов ТО**. Ссылка `/planning?mode=orders&order_month=ГГГГ-ММ` открывает выбранный месяц. Можно изменить плановое начало, трудозатраты и примечание черновика либо добавить неназначенный разовый наряд по утверждённой привязке. «Проверить изменения» показывает конкретные наряды, сроки и отличия; после подтверждения открывается сохранённый результат.
- Для назначенного наряда доступен только отдельный перенос одной строки с прежней бригадой, повторной проверкой слота и уведомлениями исполнителям. Начатые, сданные, закрытые и выпущенные в составе утверждённого плана наряды не редактируются. Изменения рабочего окна не сдвигают нормативный срок и не переписывают методику, норму или чек-лист.
- Источник таблицы — оперативные наряды PostgreSQL. XLSX создаётся заново из сохранённых строк и не заменяет импорт «Планы из Excel». Лимиты: страница 25, пакет 12, выгрузка 1000 строк; для более крупной выборки нужно сузить фильтр. Новый разовый наряд не заменяет регулярное календарное обязательство.
- Пять операций под `/api/v1/maintenance/planning/order-table` доступны ассистенту и через существующий транспорт. Инструменты v4 главного инженера формируют карточку с тем же серверным предпросмотром; назначение записывается только после отдельного согласия. Каталог: **195 операций, 774 ролевых ячейки**, без непокрытых пользовательских маршрутов. Успешная регистрация — не подтверждение качества живых ответов.
- Миграций и новых зависимостей нет. Сохранённые плановые поля лежат отдельно от нормативных в снимке наряда; ревизии, события аудита и ключ идемпотентности сохраняются в штатных таблицах.

## Воспроизведение

На отдельной PostgreSQL с учебными данными и установленным Chrome:

```powershell
python scripts/verify_web.py --order-table --pg-bin "C:/Program Files/PostgreSQL/18/bin" --grep "isolated worksheet writes"
$env:FIXRATE_ASSISTANT_AGENT_VERSION = "v2" # Старые фикстуры; тесты v4 явно включают v4.
python scripts/verify.py --backend-only --pg-bin "C:/Program Files/PostgreSQL/18/bin"
npm --prefix frontend test -- --no-file-parallelism
python scripts/assistant_capabilities.py
python scripts/assistant_acceptance_matrix.py
```

Профиль `--order-table` запускается отдельно: браузерные проверки меняют синтетический наряд и назначения, на которых основаны другие E2E. [Журнал проверок](../service/verification.md#27112026--браузерная-таблица-нарядов-то) отделяет функциональные сценарии, регрессию и небольшие замеры Chrome. Проверка кода выполнена автором: независимый агент-ревьюер не запустился из-за регионального ограничения среды. Действующие стенды и исходные книги не изменялись. Реальные регламенты, данные и облачный ассистент в прогоне не использовались; качество живого v4, допуск к защите и релизный GO из этих тестов не следуют.
