## Назначение и источник

По запросу владельца существующий интерфейс перенесён в **редактируемые слои Figma**, чтобы дальнейший редизайн начинался с фактического продукта. Это фиксация текущего состояния, без изменения дизайна или поведения приложения.

[Файл FixRate AI — UI Design](https://www.figma.com/design/YdFh9ifap89KdGu2PcN49Y) содержит страницы **«01 · Текущий UI · Desktop»** и **«02 · Текущий UI · Mobile»**. Внутри — именованные разделы и экраны с сохранёнными текстами, кнопками, таблицами, иконками и вложенной структурой. Старая заготовка с фоном и пустой панелью отсутствует; промежуточные испорченные кадры и подтверждённые дубли исключены.

Источник — `kran_dev` **`804917495200e457272fcb2103f3043dccbad91b`**. Код приложения совпадает с базой, ранее объединённой в `dev` коммитом `33d696b`. Перенос выполнен с production-сборки React/Vite, без `VITE_DEMO_MODE`. Desktop viewport — **1440×900**, mobile — **390×844**; длинные страницы сохранены целиком, поэтому высота фреймов может превышать высоту viewport.

[Машинная опись экранов](../design/2026-11-17-current-ui-figma.json) перечисляет **103 фрейма: 60 desktop и 43 mobile**. Для каждого записаны исходный маршрут, роль, размер viewport, назначение, происхождение данных и прямая ссылка на слой Figma.

## Данные и воспроизводимость

Для съёмки создан отдельный loopback PostgreSQL-кластер `fixrate_figma`, применены текущие миграции и штатные синтетические seed-данные. Дополнительно подготовлены анонимный Excel-каталог из тестовых fixtures и черновик плана. Эти данные нужны для отображения редакторов; рабочая БД и пользовательские настройки не используются.

Setup, пример сохранённого сравнения и пример переписки показаны через адресные UI-response fixtures. Сравнение взято из существующего `frontend/src/shared/mocks/data.ts`. Переписка прямо обозначена как пример отображения для макета. Это не реальные результаты AI и не доказательство качества прогноза. Для состояния приёмки тестовый отчёт переведён в ожидание решения только в отдельной БД. Окна подтверждения открыты без отправки окончательного решения.

Модели не вызываются, новые веса не скачиваются. У Python-стенда запрещены внешние сетевые назначения; официальный Figma capture script в отдельном временном Chrome-профиле передаёт только подготовленный интерфейс в выбранный владельцем файл. Cookies, пароли, токены, сессии, локальная БД и фотографии runtime в Git не входят.

Каждый кадр снимается из отдельного состояния тестового браузера. При визуальной проверке исправлены кодировка команд и перенос сохранённого открытого мобильного меню между кадрами. Испорченные варианты не входят в итоговую опись; специально открытое меню остаётся отдельным состоянием.

## Проверки и ограничения

- TypeScript и Vite production build успешны; начальный JS **123,76 KiB gzip**, Vite **4,89 с**. Это сборка исходного интерфейса, а не проверка нового редизайна.
- Каждый вошедший в опись capture подтверждён Figma как completed. Слои проверяются повторным чтением файла: наличие, размер, редактируемые тексты/векторы, размещение по страницам и отсутствие пересечений соседних фреймов.
- Контрольные рендеры сравниваются с локальным браузером. Полноэкранные скриншоты используются для проверки, а не вместо редактируемого UI.
- Исходные шрифты сохранены, включая **Segoe UI** и моноширинные семейства. Облачный MCP-редактор не располагает Segoe UI; на рабочем Windows-компьютере он установлен. Доступность Segoe UI в клиенте Figma остаётся отдельным открытым пунктом: для точного отображения и редактирования может потребоваться Figma Desktop или локальный font helper. Шрифт не заменён на Inter ради формального завершения.
- Нативные слои импорта не означают завершённую библиотеку компонентов, Code Connect или интерактивный прототип. Компонентная система и сам редизайн — следующая работа.
- Перенос не закрывает бизнес-задачи, функциональные дефекты, промышленную приёмку оркестратора, E2E-матрицу или установочные gates. Ранее открытые требования сохраняются.

## Миграция в локальный Penpot — в работе

По отдельному поручению владельца дизайн-среда переносится в **локальный Penpot**, без редизайна и удаления Figma. Целевой результат остаётся прежним: 103 редактируемых экрана, 60 desktop и 43 mobile, все 24 экранных компонента. [Опись миграции](../design/2026-11-17-current-ui-penpot.json) сохраняет ключи и Figma Frame ID; `penpot_object_id: null` и `BLOCKED` означают отсутствие подтверждённого импорта, а не потерю экрана или выполненную работу.

### Установленная среда

Развёрнут официальный **Penpot 2.19.2**, включая backend, frontend, exporter, MCP и admin console. Используется существующий Docker Desktop/Engine, отдельный Compose-проект `fixrate-design-penpot`, собственные volumes PostgreSQL 15 и assets. БД FixRate AI для Penpot не используется. Веб-интерфейс доступен только на [localhost:9001](http://localhost:9001), локальный mail catcher — на localhost:9025; PostgreSQL, Valkey и MCP не публикуются отдельными host-портами. Телеметрия backend отключена. Production приложения не изменялся.

Конфигурация: [deploy/design/penpot/compose.yaml](../../deploy/design/penpot/compose.yaml). Для воспроизведения создайте приватный env-файл вне Git с `PENPOT_VERSION=2.19.2`, `PENPOT_PORT=9001`, `PENPOT_MAIL_PORT=9025`, случайными различными `PENPOT_DB_PASSWORD` и `PENPOT_SECRET_KEY` (не менее 32 случайных байтов каждый). Фактический локальный файл — `var/penpot-migration-20261117/runtime.env`. Его значения и созданная локальная учётная запись не публикуются.

```powershell
docker compose --env-file var/penpot-migration-20261117/runtime.env -f deploy/design/penpot/compose.yaml config --quiet
docker compose --env-file var/penpot-migration-20261117/runtime.env -f deploy/design/penpot/compose.yaml up -d
docker compose --env-file var/penpot-migration-20261117/runtime.env -f deploy/design/penpot/compose.yaml ps
```

Остановка без удаления данных: тот же Compose-вызов с `stop`; запуск — `start`. Не используйте `down -v` для перезапуска: это удалит данные локальной дизайн-среды. Образы Penpot зафиксированы на версии 2.19.2; служебные образы сохраняют версии официального Compose (PostgreSQL 15, Valkey 8.1, Mailpit v1), их digests отдельно не зафиксированы.

### Официальный MCP и фактическая проверка

Используется официальный контейнер `penpotapp/mcp:2.19.2`, работающий локально в multi-user mode. Термин «remote mode» в документации протокола здесь обозначает HTTP-транспорт с ключом; облачный сервер Penpot не используется. Frontend проксирует Streamable HTTP по `/mcp/stream?userToken=…`. В текущем режиме доступны `high_level_overview`, `penpot_api_info`, `execute_code`, `export_shape`; filesystem-инструмент `import_image` не предоставляется.

Подключение воспроизводится через **Your account → Integrations → MCP Server**: включить, сгенерировать ключ, сохранить секретную ссылку, открыть файл и включить **MCP server → Connect**. Вкладка редактора должна оставаться активной. В Codex добавлена секция `[mcp_servers.penpot_local]` с локальным URL, `startup_timeout_sec = 30`, `tool_timeout_sec = 120`. Прежние подключения сохранены; приватная копия исходного config хранится в runtime-папке. Ссылка с ключом хранится только в пользовательском config и приватных артефактах. Для появления новых инструментов в уже запущенном клиенте может потребоваться переподключение/новая сессия; текущая проверка выполнена настоящим JSON-RPC-клиентом через официальный MCP endpoint.

В отдельном файле **«MCP Connectivity Check — not migrated UI»** создан board `f4927f58-4ade-808b-8008-f56fd9b6bdec` и нативный текст `f4927f58-4ade-808b-8008-f56fd9f53a72`. Второй независимый вызов прочитал текст, изменил кириллическую строку и размер board на 420×180, подтвердил `type=text` и родителя. Это **PASS создания/чтения/изменения MCP**, но **не перенесённый экран**. Файл проверки не выдаётся за готовый дизайн FixRate AI.

### Выбранный перенос и ошибка экспортера

В локальных исходных материалах не обнаружен нативный экспорт `.fig`/`.penpot`. Официальный **[Penpot Exporter](https://github.com/penpot/penpot-exporter-figma-plugin)** для Figma существует; по уточнению владельца выбран именно перенос его ZIP, а восстановление из React отложено. Новые запросы к исчерпанному Figma MCP не выполняются, ограничения Figma не обходятся. Запуск стороннего плагина через доступный Figma MCP не поддерживается; требуется обычный запуск в Figma Desktop владельца. Исходный файл сохраняется.

Владелец запустил Community Exporter **0.26.3**, но экспорт остановился: `in set_strokeStyleId: Cannot call with documentAccess: dynamic-page`, этап `processing`, слой `List`. Скачан официальный tag v0.26.3, commit **`8795e728d4b0d235f4c7d4d5c0a5066dcfcd3a3b`**. SHA-256 исходного ZIP: `52234a5222899f1ab9f583fd803d715ab8ad3e3c53e1b509fd65de50502a1200`. Неизвестные community-репозитории не использовались.

Сборка официального исходника с его lockfile позволила сопоставить позиции пользовательского стека: `Pe` — `translateGridTracks`, `Oe` — `translateGridAttributes`, `At` — обработка auto layout. В этой точке исходник **читает** Grid tracks через `tracks.map(translateGridTrack)`; синхронного присваивания `strokeStyleId` в нём нет. Поэтому сообщение setter само по себе не доказывает запись в исходный слой. Рабочая гипотеза — некорректный native callback метода host-массива Figma.

Подготовлена **локальная модификация** `0.26.3+fixrate.grid1`, а не официальный исправленный релиз: `translateGridTracks` читает элементы по индексу и сохраняет реальные fixed/flex размеры. Исходный `documentAccess: dynamic-page` сохранён; ошибки чтения данных не подавляются и Grid не заменяется безусловно на flex. Дополнительно manifest запрещает сетевые запросы плагина (`allowedDomains: ["none"]`); UI собран в development mode без ключей Sentry/Mixpanel. Проприетарные шрифты в пакет не включены. Лицензия MPL 2.0 сохранена.

Локальный результат: `var/penpot-migration-20261117/penpot-exporter-fixed/manifest.json`, ZIP сборки — `penpot-exporter-fixrate-grid1.zip` в той же runtime-папке. **Figma Desktop → Plugins → Development → Import plugin from manifest…**, выбрать этот manifest, запустить **Penpot Exporter — FixRate Grid Fix** и выбрать **All pages**. Исходный официальный репозиторий и точечные изменения сохранены локально; [patch](../../deploy/design/penpot/exporter-grid-host-array.patch) позволяет проверить состав изменения. Это обычный development plugin, без обхода лимитов MCP.

Проверки сборки: **73 test files / 494 tests passed**, включая 4 новые проверки host-массива, пустой сетки, невалидных данных и распространения посторонней ошибки; обе проверки TypeScript успешны; JS и UI собраны. Реальный запуск модификации в файле владельца и получение итогового ZIP остаются **NOT_RUN** до подтверждения. Мок native callback не заменяет Figma runtime.

Только успешный пилот разрешает масштабирование и организацию остальных экранов. Не считать пустые boards, скриншоты или непроверенный импорт выполненной миграцией. Frontend/backend, production, Git push/merge и релизы в рамках этой работы не изменяются.
