# 23.11.2026 · Сравнение пайплайнов ассистента

MVP‑11 и MVP‑08, требования PLN‑12 и AT‑08…AT‑12. Проверяемый результат включает ответ по фактической истории оборудования, точный выбор наряда на заданную дату и подтверждаемое назначение. Для пилота требуются полномочия на объекте, действующие регламенты и доступная история приёмки.

Опорная версия v3 зафиксирована коммитом `8869946`. В ветке `llm_dynamic` сравниваются штатный v3 на Qwen 3.5 4B, динамический цикл на той же Qwen и тот же цикл на DeepSeek V4 Flash. Во всех вариантах работают одни права, FastAPI и одна синтетическая база PostgreSQL. Варианты отличаются способом выбора инструментов и, в C, моделью. A сохраняет штатную подборку инструментов. B и C получают одинаковый компактный набор предметных чтений.

Экспериментальный цикл получает недавнюю историю в пределах текущего диалога, выбирает один вызов за шаг и видит его факты перед следующим решением. Сервер исполняет только зарегистрированные маршруты в контексте текущего пользователя. Итоговый текст по данным строится из результата чтения. Подготовка назначения требует явного поручения и успешного расчёта по наряду. Изменение выполняется существующим подтверждением с проверкой ревизии и аудитом. Миграции базы отсутствуют.

Фильтры `accepted_maintenance` и `equipment_accepted_maintenance` используют связанные с регламентом работы и принятые отчёты. Для исполнителя учитывается доступная история его назначений. Отсутствие принятого отчёта относится к истории системы. Поиск нарядов может применить эту же выборку оборудования, местную дату, состояние и SQL-порядок с `limit=1`.

## Проверка

Корпус включает 50 новых диалогов и 101 реплику для главного инженера, инженера, руководителя и исполнителя. В том числе проверяется последовательность «Какое необслуженное оборудование есть?» → «Какое из них ближайшее на завтра?» → «Только одно надо ближайшее». Каждая реплика сверяется с SQL по фактам, лишним строкам, дате и успешному источнику. Диалог проходит, когда проходят все его реплики. Перед переходом к следующему варианту сравниваются отпечатки предметных таблиц. Карточка и подтверждение проверяются отдельно.

Вариант C использует авторизованный синтетический набор и настроенный AI Tunnel. Запуск ограничивает внешний запрос адресом этого провайдера. Обычный ручной стенд работает через локальный Ollama.

```powershell
python -m agent_reliability_lab.run_pipeline_comparison --output reports/pipeline-local
python -m agent_reliability_lab.summarize_pipeline_comparison reports/pipeline-local/run/agent-audit/pipeline-comparison
```

Для C предусмотрен явный параметр `--cloud-config` с приватным конфигурационным файлом тестового провайдера. По умолчанию сравнение выполняет A и B с локальной моделью. Артефакты, отпечатки и трассы сохраняются в игнорируемом `reports/`. [Модельный цикл LangGraph](https://docs.langchain.com/oss/python/langgraph/workflows-agents).
