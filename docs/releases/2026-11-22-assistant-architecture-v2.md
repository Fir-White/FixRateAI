## Что изменилось в коде и контрактах

- `dialogue_routing`, `semantic_plan` и `request_coverage` определяют тип запроса, сохраняют буквальные опоры, область, запрет изменений и результат проверки покрытия в `request_spec`. При составном запросе проверка пропусков может добавить явно запрошенное чтение. Разговорный ответ может завершиться без поручения. Ollama и AITunnel принимают типизированный контракт.
- `semantic_execution`, `objective_scope`, `outcome_contracts` и `evidence` связывают чтения с проверенным ID, сроком, областью и полнотой. Пояснение сохранённой просрочки строится после чтения карточки. Соседние цели используют один проверенный поиск ID. В записи доказательства различаются пустая выборка, частичный ответ, отказ в доступе, недостающий вход, отказ источника и устаревшее чтение.
- `GET /api/v1/assistant/workspace/tasks` принимает фильтры `equipment_id`, `unfinished_only`, `starts_on` и `ends_on`. Фильтр оборудования использует связь наряда с объектом, просрочка определяется по нормативному сроку. `GET /api/v1/assistant/workspace/equipment/{equipment_id}/history` с `latest_only` выбирает принятую попытку по фактическому времени. Вариант запроса истории с диапазоном дат продолжает работать. `calendar-evidence` поддерживает `approved_only` и возвращает область расчёта. [Контракты backend](../service/backend.md)
- `task_execution` сохраняет цепочку «начало → чек‑лист → черновик → сдача → итог». Подготовка действий использует действующие проверки назначения, роли и ревизии. Тайм-аут локального фотоанализа берётся из серверного лимита операции. Фотоанализ служит входом для приёмки инженером.
- `GET /api/v1/assistant/actions` и `assistant_action_history` выдают постраничную историю в пределах пользователя, объекта и роли. UI открывает диалог по ссылке из `/assistant?view=actions` и сохраняет черновик при смене вкладок. Маршруты `/executor/tasks` и `/executor/reports` используют текущие назначения и `activeExecutionId`. [Контракты интерфейса](../service/web.md)
- `contracts/assistant-tools.json` и `contracts/assistant-acceptance.json` пересобраны. Проверка охватывает 179 зарегистрированных операций; исполненная приёмка каждой роли и операции учитывается отдельно. MCP использует тот же каталог и существующий transport.

## Миграция и эксплуатационные границы

Миграция [027](../../database/migrations/027_assistant_turn_claim.sql) добавляет nullable `assistant_turns.worker_claimed_at`. Дедлайн и атомарный захват определяют, какой запуск может выполнить поручение. После истечения пользователь продолжает от того же корня с новой авторизованной сессией. Завершённые и неопределённые записи сохраняют прежние идентификаторы и исходы. Старые JSON-снимки читаются через совместимый workflow; колонки предыдущих миграций и история действий доступны для проверки и отката приложения.

Автономному worker после перезапуска нужен обновляемый служебный контекст авторизации. Для постоянной базы знаний требуется потребитель событий CR‑17, индекс актуальных ревизий и проверка ACL. Подключение редактора XLSX требует preview и применения к проверенной ревизии файла через подтверждаемую операцию. [Точки расширения](../architecture/assistant-architecture-v2.md#точки-расширения)
