# Мобильная Aurora: Canvas в общем lifecycle

- ID: `ADR-2026-11-02-mobile-aurora-canvas`
- Дата: 2026-11-02
- Статус: принято в локальной frontend-ветке `feature/frontend-kran`
- Задача: мобильная динамика Aurora, непрерывный фон при изменении viewport и устранение задержек на Android; внешняя карточка не задана.

## Контекст

Мобильный breakpoint прежде полностью останавливал Aurora. После включения деформации через существующий SVG пользователь сообщил о сильных задержках на реальном Android. Desktop SVG при этом менять не требовалось. Широкие Gaussian-фильтры и обновление path `d` заставляли браузер заново отрисовывать декоративные слои.

Отдельно воспроизведены обрыв ограниченной по высоте сцены на длинной форме и скрытие логотипа после нативного восстановления прокрутки при reload. Это проблемы viewport/scroll policy, а не геометрии фирменного SVG.

## Решение

Сохранить общий `AuroraScene`, детерминированную геометрию и единственный animation loop. Desktop продолжает использовать прежний SVG и частицы. Mobile использует тот же canvas с ограниченным backing store и без Gaussian-фильтров во время кадра: кэшированный профиль свечения отрисовывается вложенными native Bézier-stroke по общему пути. Цвета и ambient кэшируются при resize. Новый renderer включается только после готовности Canvas, с SVG fallback.

Параметры профиля, математические границы и lifecycle описаны только в [web](../service/web.md#геометрия-пауза-и-производительность). Системный reduced-motion обязателен; пользовательский переключатель не возвращается. Ввод, формы и фирменные SVG логотипа не переносятся в Canvas.

Для мобильного фона использовать стабильный large viewport, а для минимальной высоты естественно прокручиваемой формы — dynamic viewport. Одноразовая нормализация свежего auth-документа отделена от resize, фокуса и пользовательской прокрутки. Точные правила находятся в [адаптивности](../service/web.md#адаптивность).

## Причины выбора

Canvas устраняет мобильные SVG filter raster и изменения `d` без второй системы движения и новых зависимостей. Первый грубый вариант свечения отклонён из-за видимых полос; Gaussian-opacity quantiles сохранили мягкость. Текстурные сегменты усложнили бы стыки и кэш, а необходимость WebGL измерениями не подтверждена.

Пользователь после обновления на телефоне сообщил: «Стало заметно плавнее». Это качественная проверка на устройстве, не измерение FPS. Числовые результаты и условия сравнения SVG/Canvas находятся в [датированном протоколе](../service/verification.md#02112026-мобильная-aurora-viewport-и-производительность).

## Последствия

Мобильная отрисовка оптически приближает SVG, но не обязана совпадать с ним побайтно: меньший raster может давать мелкую фактуру на увеличенных снимках. Форма, текст и логотип остаются резкими нативными DOM/SVG-элементами. Ресурсы Canvas освобождаются при смене режима и unmount.

Desktop проверяется отдельными эталонными path-фазами. Мобильные изменения требуют проверки viewport, фазы паузы, длительного движения, читаемости и измерений при одинаковых условиях. Эмуляция Chrome и пользовательский отзыв не доказывают производительность всех Android GPU, реальной клавиатуры и панелей браузера.
