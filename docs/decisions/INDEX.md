# Архитектурные решения

Существующие восемь ML/CV-решений сгруппированы по дате и теме; прежние ADR-001…ADR-008 сохранены внутри записей. Индекс отсортирован от новых дат к старым. ID не связан с номером задачи.

| Дата | ID | Тема | Статус |
|---|---|---|---|
| 2026-10-28 | [ADR-2026-10-28-hidden-operations](2026-10-28--hidden-operations.md) | Скрытые операции не проверяются по фото | Принято |
| 2026-10-27 | [ADR-2026-10-27-photo-review](2026-10-27--photo-review.md) | Локальный фотоанализ и человеческая приёмка | Принято |
| 2026-10-27 | [ADR-2026-10-27-data-provenance](2026-10-27--data-provenance.md) | Происхождение данных и неизменяемый снимок | Принято |
| 2026-10-26 | [ADR-2026-10-26-random-forest](2026-10-26--random-forest.md) | Random Forest для экспериментального прогноза | Принято |
| 2026-10-26 | [ADR-2026-10-26-ml-integration](2026-10-26--ml-integration.md) | Библиотечная интеграция ML и общий контракт | Принято |

Новое решение создаётся по [шаблону](ADR-TEMPLATE.md) с именем `YYYY-MM-DD--topic.md` и ID `ADR-YYYY-MM-DD-topic`. Ссылку на задачу добавляют только при наличии настоящей задачи. Реализация решения сама по себе не доказывает достижение ожидаемых метрик.

## Применение записей

Это перенос существующих принятых решений, а не новая оценка качества. Числовые ожидания раннего проекта не считаются результатами замеров. Текущие параметры, ограничения и связи с кодом — в [ML/CV](../service/ml.md), [API](../service/backend.md) и [оркестраторе](../service/planning.md).
