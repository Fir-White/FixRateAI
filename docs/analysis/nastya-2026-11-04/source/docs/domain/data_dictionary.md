# Проектная документация: Предметная модель расширяемого графика ТО/ППР

## 1. Текстовое описание модели связей (ERD)

Предметная модель спроектирована в соответствии с принципами нормализации баз данных (3НФ), что позволяет исключить избыточность данных и обеспечить гибкое масштабирование при добавлении новых видов инженерного оборудования и регламентных работ.

### Основные сущности и связи (ERD)

1. **equipment_objects (Объект обслуживания)**  
   - Описание: Крупный объект инфраструктуры или здание (например, Главное здание, ИТП-1).  
   - Связь с engineering_systems (1:N): Один объект обслуживания содержит множество инженерных систем.

2. **engineering_systems (Инженерная система)**  
   - Описание: Функциональный контур (например, Система теплоснабжения, Система ХВС/ГВС).  
   - Связь с equipment_items (1:N): Одна инженерная система включает множество единиц конкретного оборудования.

3. **equipment_items (Единица оборудования)**  
   - Описание: Конкретный физический узел или прибор с уникальным инвентарным номером (например, Манометр МП3-У №104, Теплосчетчик ТЭМ-104).  
   - Почему отделена: Отделение конкретного экземпляра от шаблона работы позволяет привязывать одну и ту же регламентную операцию (например, «Контроль давления») к сотням однотипных приборов без дублирования текстов.

4. **operation_templates (Шаблон операции ТО)**  
   - Описание: Справочник технологических операций (например, «Контроль параметров показаний приборов (давление, температура)» — код 1.1). Содержит нормативную трудоемкость (нормо-часы) и требования к квалификации персонала (`[ДЕМОНСТРАЦИОННОЕ ДОПУЩЕНИЕ]`).  
   - Почему отделена от факта выполнения: Шаблон описывает, *что* нужно делать абстрактно, а таблица календарных фактов хранит историю, *когда*, *кем* и *с каким результатом* эта операция выполнялась на конкретном объекте.

5. **regulations (Регламент / Привязка операции к оборудованию)**  
   - Описание: Связующая таблица (M:N), определяющая, что конкретная единица оборудования (`equipment_item_id`) должна обслуживаться по определенному шаблону (`operation_template_id`) с заданной периодичностью (`1/день`, `1/квар`, `5/год`).

6. **brigades (Бригада) и employees (Сотрудник)**  
   - Описание: Кадровый состав. Таблица `employees` хранит данные о работниках, их квалификации и разряде (`[ДЕМОНСТРАЦИОННОЕ ДОПУЩЕНИЕ]`). Сущность `brigades` объединяет сотрудников для выполнения тяжелых работ (например, ТО2 с требованием 2 человек).

7. **maintenance_tasks (Календарное выполнение / Факт работы)**  
   - Описание: Конкретная задача (наряд-заказ), сгенерированная на основе регламента на определенную дату. Сохраняет операционный статус выполнения (`created`, `assigned`, `in_progress`, `on_review`, `returned`, `completed`), отдельный булев признак просрочки (`is_overdue`), фактические трудозатраты и ссылки на назначенного сотрудника или бригаду.

## 3. Бизнес-правила (Периодичность, просрочка и демонстрационные допущения)

1. **Правило «1/день» (Ежедневные обходы — ТО1, операции 1.1–1.3):**  
   - *Смысл:* Операция должна выполняться строго ежедневно (365 дней в году, включая выходные — подтверждено 31/31 днем в октябре в Excel заказчика).  
   - *Обработка:* Планировщик автоматически создает задачу на каждый календарный день в 00:00. Дедлайн устанавливается строго на текущие сутки (23:59).  
   - *Исключения и Guardrail (Признак `is_overdue`):* Перенос обязательного срока ТО на более позднюю дату технически заблокирован системой. Если до 23:59 задача не переведена в `completed`, система **сохраняет текущий операционный статус задачи** (`created`, `assigned`, `in_progress`, `on_review` или `returned`), выставляет отдельный признак `is_overdue = true` и формирует эскалацию на Главного инженера.

2. **Правило «1/квар» (Квартальные проверки — ТО2, операции 1.5, 1.6):**  
   - *Смысл:* Проведение регламентных работ 1 раз в квартал (4 раза в год).  
   - *Обработка (`[ДЕМОНСТРАЦИОННОЕ ДОПУЩЕНИЕ]`):* Так как в исходном Excel-графике на октябрь клетки для ТО2 пустые, для планировщика принята демонстрационная политика отсчета `+3 месяца` от даты предыдущего ТО (`last_maintenance_date`). Если расчетная дата выпадает на выходной (суббота/воскресенье), она переносится на ближайший следующий рабочий день (понедельник) при условии, что перенос не выходит за рамки целевого квартала и не нарушает регламент.

3. **Правило «5/год» (Циклическое тяжелое обслуживание — ТО2, операция 1.4):**  
   - *Смысл:* Выполнение сложных работ («Чистка всех узлов и агрегатов системы», 2 чел., 60 нормо-часов) 5 раз в год.  
   - *Обработка (`[ДЕМОНСТРАЦИОННОЕ ДОПУЩЕНИЕ]`):* В исходном Excel заказчика точные месяцы для режима `5/год` не указаны. В качестве демонстрационного допущения в алгоритме заложен равномерный шаг (интервал ~73 дня / 2.4 месяца от точки старта или ввода оборудования в эксплуатацию) с переносом выходных дней на ближайший рабочий день.

## 4. Эталонные JSON-примеры

### Пример 1: Шаблон операции (`operation_templates`)

```json
{
  "template_id": "op-tmpl-101",
  "name": "Контроль параметров показаний приборов (давление, температура)",
  "to_type": "ТО1",
  "norm_hours": 1.0,
  "required_qualification": "Слесарь-сантехник 3 разряда",
  "required_workers": 1
}
```

### Пример 2: Регламент — привязка операции к оборудованию (`regulations`)

```json
{
  "regulation_id": "reg-501",
  "item_id": "eq-item-991",
  "template_id": "op-tmpl-101",
  "frequency_type": "daily",
  "frequency_value": "1/день"
}
```

### Пример 3: Факт выполнения (календарная задача) с назначением на сотрудника (`maintenance_tasks`)

```json
{
  "task_id": "task-8840",
  "regulation_id": "reg-501",
  "planned_date": "2026-10-28",
  "status": "completed",
  "is_overdue": false,
  "assigned_employee_id": "emp-12",
  "assigned_brigade_id": null,
  "actual_norm_hours": 1.0,
  "completion_timestamp": "2026-10-28T14:15:00Z"
}
```

### Пример 4: Критически важно! Связь одной операции с несколькими экземплярами оборудования (M:N без дублирования)

Один и тот же шаблон операции (`op-tmpl-101` — Контроль параметров) через промежуточную таблицу регламентов (`regulations`) одновременно привязан к трем разным манометрам и датчикам температуры в тепловом пункте (`reg-501` $\rightarrow$ `eq-item-991`, `reg-502` $\rightarrow$ `eq-item-992`, `reg-503` $\rightarrow$ `eq-item-993`). При этом текст операции и норматив хранятся в единственном экземпляре:

```json
{
  "operation_template": {
    "template_id": "op-tmpl-101",
    "name": "Контроль параметров показаний приборов (давление, температура)",
    "to_type": "ТО1",
    "norm_hours": 1.0
  },
  "linked_equipment_instances": [
    {
      "regulation_id": "reg-501",
      "equipment_item": {
        "item_id": "eq-item-991",
        "name": "Манометр подающей линии ТС",
        "serial_number": "MN-2024-01"
      }
    },
    {
      "regulation_id": "reg-502",
      "equipment_item": {
        "item_id": "eq-item-992",
        "name": "Манометр обратной линии ТС",
        "serial_number": "MN-2024-02"
      }
    },
    {
      "regulation_id": "reg-503",
      "equipment_item": {
        "item_id": "eq-item-993",
        "name": "Датчик температуры теплоносителя",
        "serial_number": "DT-2024-15"
      }
    }
  ]
}
```

## 5. Проверка по Критериям Приемки (Чек-лист)

- ☑ **Одна операция назначается разному оборудованию:** Подтверждено архитектурой «Шаблон операции» $\rightarrow$ «Регламент» $\rightarrow$ «Единица оборудования» (Пример 4, идентификатор `reg-501` строго согласован с `eq-item-991` во всех файлах).  
- ☑ **Данные не дублируются без причины (нормализация):** Тексты операций, нормативы и квалификация хранятся в справочнике `operation_templates` в единственном экземпляре.  
- ☑ **Не смешаны типы: оборудование, конкретный экземпляр и операция:** Сущности строго разделены на уровни (`equipment_objects` $\rightarrow$ `engineering_systems` $\rightarrow$ `equipment_items` для оборудования и `operation_templates` для работ).  
- ☑ **Просрочка отделена от статуса:** Флаг `is_overdue` выделен в отдельный атрибут `maintenance_tasks`, не затирающий рабочие статусы (`in_progress`, `on_review` и др.).  
- ☑ **Демонстрационные допущения явно помечены:** Требования к квалификации, перенос выходных для ТО2 и распределение `5/год` имеют явную маркировку.
