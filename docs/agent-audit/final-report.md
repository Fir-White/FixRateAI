## Почему одного зелёного прогона оказалось мало

- Ручной пересмотр старого 21/21 live нашёл выдуманные **2 чел·ч** при пустом B2/quantity=2. Oracle был слабым; он усилен, AG-009 исправлен.
- Переименование не работало из-за самого транспорта: default=null добавлялись первой сериализацией и отвергались второй проверкой. До AG-015: **5 failed/6 passed**.
- Frozen 75a1fa9: round 1 **1158 passed**, round 2 **1 failed/1157 passed**, одинаковый hash/source_stable=true. Модель дважды передала лишний name, затем назвала ошибку пустым реестром. Красный повтор сохранён, а не заменён первым успехом.
- Отдельные C4 red: **10 failed/7 passed** для HTTP-fault/grammar; **5 failed** для employment metadata. Проверка одной role/revision скрывала потерю дат, поэтому live oracle теперь сравнивает остальные поля SQL-строки целиком.
- Дополнительный vision-срез: **1 failed/79 passed**. Actions пусты, но модель сообщила о записи показания. Исправлена структура ответа, oracle теперь запрещает и такую ложную формулировку.

Исходные красные протоколы не удалены. Collection error отсутствующего jsonschema отдельно помечен как ошибка тестовой среды; новая зависимость не установлена. Set/const oracle явно ограничен проверкой envelope и не выдаётся за полный JSON Schema engine. Ошибки fixture/ожидаемой старой фразы не выдаются за новые продуктовые дефекты.

## Успешные цепочки и независимые oracle

1. **Реестр:** вопрос о текущем оборудовании → обязательный equipment_find текущего scope → backend name/code/total. 31 запись и страница 25 явно различаются; дополнительный фильтр/второе действие не отбрасывается. Ошибка 401/403/404/422/5xx не подменяется пустым результатом. Широкий multisite обзор остаётся отдельным существующим потоком.
2. **Регламент:** RT-PUMP → фактический equipment_id → regulations_read → 1 опубликованная конфигурация, 1 операция, 0 неопубликованных; периодичность месяц, начало 2027-01-01. Ответ отмечает будущую дату, а не объявляет ТО необходимым сегодня. Источник не Excel и не пустой календарь.
3. **Изменения:** chief готовит переименование; до approval SQL неизменён; после подтверждения имя Насос DELTA проверенный, revision 2 → 3; replay не записывает второй раз. Admin меняет другого сотрудника executor → engineer, revision 1 → 2, сохраняя employment dates/остальные поля. Установка bearing-rt сохраняет явно заданные 90/100 hour без придуманной даты замены.
4. **Потеря ответа:** пять faults после настоящего backend commit → uncertain → три подтверждения одной команды → dispatch=1, SQL count=1. Это fault injection после реальной записи, не фиктивный положительный ответ инструмента.
5. **Excel:** B2 пусто/C2=2 → readiness называет ячейки и сообщает «Численность не рассчитана». Оригинальный каталог прочитан только локально: 217 операций, 1275 отметок, 217 отсутствующих норм, ready_count=0. Исходные файлы не менялись и не передавались модели.
6. **Фото:** только synthetic PNG → настоящая native vision → typed label/value/unit → RT-FOTO-7, 1.2 bar, фиксированное отсутствие записи/приёмки. Инструкция внутри картинки не становится действием. Неизвестное не заменяется нулём; явное сохранение/изменение/дополнительная аналитика остаются обычным workflow.

Подробные ответы/trace/tool_evidence — в ignored reports/logs/var, только с искусственными данными. Auth headers, пароли, ключи, raw images и скрытые рассуждения не входят в журнал. [Манифест](changed-files.md) перечисляет **76 изменённых файлов** cumulative diff кода/тестов/документации. ## Явный остаток

- **ENV-001:** legacy SQL-test ожидает состояние после 009, но старый runner запускает его после 021. Agent-only проверяет свежую актуальную схему и повтор migrate/seed, не выдаёт это за успешный legacy upgrade.
- **ENV-003 / strict-xfail:** старый demo/unknown test требует раннюю AI-дату, QA04 требует fallback. Сохранён консервативный fallback; бизнес-ожидание не переписано ради зелёного результата.
- Не выполнено 300 свободных LLM-диалогов и не доказан каждый положительный путь всех 167 возможностей. Более 300 самостоятельных транспортных/сценарных границ выполнены; они явно отделены от генеративных эпизодов. Проверены выбранные synthetic XLSX/PNG атаки, а не все форматы и комбинации.
- What-if внезапного отсутствия, multi-site solve, полные показатели смен/простоя, ресурс без темпа наработки и часть MVP остаются отсутствующими/частичными. Аудит не подменяет их реализацию.
- UI/mobile и полный фото-цикл исполнителя не переоценивались. Typed reader узкий: одно изображение, однозначная просьба о маркировке/числе/единице; остальные задачи проходят общий агентный workflow. Неразборчивое/неподдержанная единица остаются неизвестными. 4B-модель всё ещё может ошибаться; серверные guards не означают отсутствие всех галлюцинаций.

Коммиты кода: 32c08bf → 5a20d17 → 75a1fa9 → e323d4c; у каждого подробный body. Окружение, команды воспроизведения, матрица требований и журнал циклов — в [README аудита](README.md). Это проверяемый срез качества агента с остатком, не сертификат завершения всего MVP.
