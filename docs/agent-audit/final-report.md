## Что исправлено

Подтверждены и исправлены **15 классов дефектов**. Красные воспроизведения, первопричины и adjacent-проверки находятся в [реестре](known-defects.md).

| Дефект | Итоговое поведение |
|---|---|
| AG-001, личный чат директора | Разрешён только собственный conversation DELETE; предметные запреты роли сохранены |
| AG-002, противоречивые агрегаты | Evidence gate проверяет арифметику, полноту, даты, scope и источник до полного отчёта |
| AG-003, потерянные условия запроса | Когорты/происхождение/поддержанные периоды сохраняются; неподдержанное уточняется |
| AG-004, составные read-аргументы | Максимум две безопасные GET-коррекции; неизвестные селекторы, 403/5xx и writes не ретраятся |
| AG-005, неверный JSON Ollama | Диагностика без исходного текста; одна inference-retry; native object wire устраняет двойное JSON-кодирование |
| AG-006, закреплённая бригада | Frozen segment сохраняется целиком, включая порядок исполнителей |
| AG-007, ответ без реального поиска | Явный код проверяется по backend; literal code не теряется за страницей похожих названий |
| AG-008, чужой или неверный регламент | Читаются service-configurations конкретного equipment_id; пустые задания не означают отсутствие регламентов |
| AG-009, quantity вместо нормы | Пустая норма остаётся null; readiness указывает ячейки и запрещает выдумывать численность |
| AG-010, открытая hex36-строка в trace | Свободный текст хешируется; открытый UUID разрешён только в полях идентификаторов |
| AG-011, unknown uncertainty | Неизвестность не становится доказательством раннего срока из-за calibrated=true |
| AG-012, подменённый ALG02 | Алгоритмическая дата сверяется с обязательством frozen snapshot |

Особенно важен AG-015: live-переименование обнаружило ошибку собственного транспорта. Вторая строгая проверка отклоняла поля, которые добавила первая сериализация. Отдельные пять PATCH-вариантов дали **5 failed/6 passed** до исправления. Исправлена field-presence семантика, а не ослаблен backend. Явный недопустимый null продолжает отклоняться.

У AG-005 дополнительный holdout выявил сбой даже после хорошего раннего прогона: **1 failed/72 passed**, две невалидные JSON-строки подряд. Поэтому один удачный повтор не считался устранением дефекта. Native adapter теперь принимает объект по своей грамматике и переводит его в прежнюю canonical DTO; облачная strict-схема сохранена. Eval/regex-исполнения и угадывания аргументов нет.

## Реальные успешные цепочки

1. Вопрос о регламентах RT-PUMP → backend-поиск разрешённого оборудования → фактический equipment_id → regulations_read → **1 опубликованная конфигурация, 1 операция, 0 неопубликованных**. Периодичность — месяц, начало **2027-01-01**; ответ прямо отмечает будущую дату, не объявляет работу необходимой сегодня. Источник — конфигурация актива, не Excel и не пустой календарь.
2. Chief-engineer просит переименовать RT-PUMP → equipment_edit proposal → SQL до approval не изменён → подтверждение → имя **Насос DELTA проверенный**, revision **2 → 3** → replay не меняет данные. Аналогично admin меняет другого сотрудника executor → engineer, revision **1 → 2**; установка bearing-rt сохраняет **90/100 hour** из явно заданных тестовых данных, без выдуманного срока замены.
3. Пять вариантов потери ответа после настоящего backend commit → status=uncertain → три подтверждения той же команды → **dispatch=1, SQL count=1**. Это fault injection после реальной записи, не фиктивный положительный ответ инструмента.
4. Synthetic XLSX: Audit!B2 пусто, C2=2 → readiness называет обе ячейки и прямо сообщает «Численность не рассчитана». Quantity не превращается в норматив. Оригинальный каталог также прочитан локально: **217 операций, 1275 отметок, 217 отсутствующих норм, ready_count=0**; исходные файлы не изменены и не отправлялись модели.

Очищенные подробные ответы/trace/tool_evidence находятся в ignored reports/agent-audit-frozen-75a1fa9/round-1/agent-audit. Там только искусственные данные. Auth headers, пароли, ключи и скрытые рассуждения не журналируются. Публичный [манифест изменённых файлов](changed-files.md) перечисляет 68 файлов среза кода; последующий коммит сохраняет только окончательные доказательства/документацию.

## Оставшиеся ограничения

- **ENV-001:** исторический SQL upgrade-test ожидает состояние после 009, но старый runner запускает его после 021. Agent-only проверяет свежую актуальную схему и повтор миграций; он не выдаёт это за успешный legacy upgrade. Это ограничение явно сохранено.
- **ENV-003 / один xfail:** прежний demo/unknown test требует ранний AI-срок, QA04 требует fallback при той же неизвестности. Сохранён консервативный fallback; противоречие не «решено» подгонкой ожидаемого результата.
- Не выполнено 300 свободных LLM-диалогов и не доказан полный положительный путь каждой из 167 возможностей. Более 300 самостоятельных транспортных/сценарных границ выполнены и описаны отдельно. Инъекции через synthetic XLSX/PNG проверены, но не все форматы и комбинации атак.
- What-if внезапного отсутствия, multi-site solve, полные показатели смен/простоя, календарный ресурс без темпа наработки и часть MVP остаются отсутствующими/частичными. Аудит не подменяет их реализацию.
- UI/mobile и полный фото-цикл исполнителя не переоценивались. Маленькая 4B-модель всё ещё ошибается в аргументах; ограниченное восстановление и серверные проверки не означают отсутствие всех галлюцинаций.

Контракты сохраняют 167 capability; изменены реальные cohort/asset_code query и описание view.path. Новые policy/method теги сохраняют происхождение решений, старые записи не переписываются. Миграций и правок frontend нет. Воспроизводимость, окружение, матрица требований, журнал циклов и команда запуска — в [README аудита](README.md).
