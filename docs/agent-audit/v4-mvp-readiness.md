# Готовность AI-MVP

**Статус:** новая реализация доступна в dev через штатный `/assistant`; готовность к защите определяется живыми сценариями и не следует из успешной сборки или тестов транспорта.

- [x] Новый маршрут активен в изолированном dev и доступен обеим ролям через SPA.
- [x] Проверены scoped-чтения, отклонение устаревшей карточки, отзыв назначения и однократная запись.
- [x] Подтверждена передача пикселей и контекста выбранного наряда в модель.
- [ ] Строгая приёмка содержательности всех диалогов и трёх фотоисходов.
- [ ] Целевые проценты и p95 для достаточно большого и повторяемого корпуса.
- [ ] Сравнение качества нового цикла на облачной модели с согласованным бюджетом.

| Область | Что доступно в реализации | Условия |
|---|---|---|
| Инженер | Поиск всех категорий нарядов, календарь, карточки проверок, серверный подбор и предложение назначения | Без плановой даты, длительности и подтверждённого времени/допуска назначения нет |
| Исполнитель | Только свои задания, карточка, снимок инструкций, регламент, чек-лист и замечания | Проверки не дают доступ к чужим работам; действие «начать» и отправка отчёта остаются в существующем интерфейсе |
| Фото | Предварительная оценка реальных байтов текущего фото и доступных снимков отчёта | Локальная Qwen с vision. Чат-вложение само по себе не прикрепляет файл к отчёту |
| Данные | Миграция 029 дополняет схему, существующие сообщения, действия и фото сохраняются | Для существующей БД требуется резервная копия, проверка на копии и отдельное разрешение на смену стенда |

Назначенный исполнитель и создатель хранятся отдельно. Универсальное поле ответственного инженера и причина задержки не гарантированы схемой наряда; при отсутствии исходного факта нельзя их подставлять.

## Запуск и проверка

После исправления карточки отдельно запущен [синтетический стенд](http://127.0.0.1:8766/assistant) с локальной Qwen (8K) и миграцией 029. `/api/health`, вход и `capabilities` проверены для инженера и исполнителя. Реквизиты те же, что на 8765; прежний стенд и его история сохранены. Нативный сервер и PostgreSQL привязаны только к `127.0.0.1`.

Для собственного синтетического стенда: `DATABASE_URL` локальной PostgreSQL, отдельный `PHOTO_STORAGE_ROOT`, `ASSISTANT_PROVIDER=ollama`, точный тег `OLLAMA_CHAT_MODEL` и `OLLAMA_CHAT_DIGEST` из локального `/api/tags`. Оставьте `FIXRATE_ASSISTANT_AGENT_VERSION=v4` (по умолчанию) и `FIXRATE_ASSISTANT_V3_PIPELINE=v3` (значение по умолчанию, использующееся только при откате на v3).

1. В `frontend/` выполните `npm run build`. Примените миграции к **выбранной синтетической** БД и отдельно выполните demo seed. См. [запуск сервиса](../service/runtime.md).
2. Запустите `python scripts/start_backend.py --host 127.0.0.1 --port <свободный_порт>`. Инженер открывает `/assistant` и проверяет выбранный состав в карточке. Исполнитель открывает собственное задание → **Спросить ИИ по наряду**, затем прикладывает фото или задаёт вопрос. Чат открывается отдельно и не сбрасывает черновик отчёта.
3. `GET /api/v1/assistant/capabilities` должен вернуть `prompt_version=fixrate-tool-calling-v4`; сохранённый turn — `execution_engine=v4`, `workflow=null`, `model_ref` фактически ответившего провайдера. Именно эти поля, а не имя Git-ветки, определяют использованный маршрут.

Изолированный прогон, включая Chrome и живую модель:

```powershell
$env:FIXRATE_ASSISTANT_AGENT_VERSION = 'v3' # только настройка исторической тестовой фикстуры, новые диалоги в тестах идут через v4
$env:FIXRATE_TOOL_AGENT_BROWSER = '1'
python -B scripts/verify_agent_local.py --live --output reports/tool-agent-v4-new-run --pytest-target tests/agent_reliability_lab/evals/test_tool_agent_v4.py tests/agent_reliability_lab/evals/test_tool_agent_browser.py
```

Для RTX 4050 на 6 ГиБ можно отдельно проверить короткий контекст командой из примера с `--num-ctx 8192`. Фактический offload проверяется `ollama ps`; при запуске приложения аналогичная настройка — `OLLAMA_CHAT_NUM_CTX=8192`. Качество длинных диалогов зависит от размера контекста, поэтому замеры 8K и 32K не следует смешивать.

Откат без удаления столбца или истории: явно задать `FIXRATE_ASSISTANT_AGENT_VERSION=v3` или `v2`, `FIXRATE_ASSISTANT_V3_PIPELINE=v3` и перезапустить только выбранный dev-сервер. Уже запущенные Docker-приложения и production не менялись. [Результаты и ограничения](v4-mvp-benchmark.md).
