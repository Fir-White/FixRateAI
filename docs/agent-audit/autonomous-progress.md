# Контрольная точка автономного аудита

## Cycle 0 — изоляция и подготовка

- Исходная ветка kran_dev и коммит f817875 сохранены без изменений.
- Создан отдельный worktree/ветка в локальном клоне внутри private var исходной рабочей папки.
- Прочитана директива, AGENTS.md, контракты и отчёты предыдущих дефектов; найдены обе версии ТЗ и Excel-основания.
- Docker заблокирован правами; запрос повышения прав не выполнялся. Есть нативный PostgreSQL 18.
- Новые зависимости OR-Tools/Hypothesis недоступны из-за сетевого sandbox. Не подменяются фиктивным solver.
- Подтверждена доступность локальной Ollama без использования производственных ключей.
- В существующий verify.py добавлен --backend-only: сохраняются прежние Python/API/SQL проверки, frontend не запускается вне области аудита.

Следующий приоритет: запустить чистый baseline на отдельном PostgreSQL; воспроизвести найденное несовпадение директорского доступа к управлению собственным диалогом; расширить контрактную матрицу и живые агентные сценарии.

## Cycle 1 — действующие контракты и безопасность

- Нативный изолированный PostgreSQL: 112 прежних проверок прошли. Docker не использован, прав не повышали.
- OR-Tools и зависимости восстановлены из существующего локального pip-cache в отдельное окружение. Готов настоящий solver; Hypothesis не установлен. Для генеративных проверок используется детерминированный stdlib, это не запуск Hypothesis.
- AG-001: директор не мог удалить собственный диалог. Воспроизведение: 1 failed / 18 passed. Узкий фикс приватного DELETE, смежная регрессия: 57 passed.
- Генерируемый корпус: 619 независимых проверок схем, отказов по ролям, чужих диалогов и неизвестных аргументов для 167 зарегистрированных инструментов. После усиления oracle проходят все 619. Это проверки транспортов, не 619 диалогов с моделью.

## Cycle 2 — аналитические доказательства и живой baseline

- AG-002: десять повреждений реальных ответов аналитики ошибочно принимались как полный отчёт. До: 10 failed. Проверки согласованности счётчиков, страниц, дат, норм и дублей добавлены; общая регрессия с матрицей: 654 passed.
- AG-003: обработчик незавершённых заданий молча отбрасывал месяц/день/источник/статус и захватывал запросы завершённых заданий. Независимый fixture с четырьмя заказами: 10 failed / 1 passed. Исправлены серверный cohort, строгая схема API и разрешение поддержанных дат по серверным часам; результат ещё проверяется.
- AG-004: живой qwen3.5:4b-q4_K_M не смог прочитать имеющееся оборудование/ТО: null вместо query и выдуманная цепочка view.path; комбинированная ошибка не восстанавливалась за один retry. Введено одно восстановление необязательных оболочек и проекции с сохранением серверных селекторов; повторный live-прогон предстоит.
- Первый live-прогон: 7 сценариев, 4 passed / 3 failed. Два реальных отказа чтения и одна ошибка тестового oracle (охранный детерминированный отказ ошибочно требовал LLM-inference). Identity/offtopic, инъекция в имя оборудования, создание с подтверждением и повторным подтверждением прошли. Ошибка oracle исправлена и не считается дефектом продукта.

Основной worktree, исходная БД, фото и запущенный сайт не изменялись. Отчёт — контрольная точка; аудит продолжается.

## Cycle 3 — восстановление аргументов и настоящая модель

- Детальная безопасная ошибка nested arguments_json помогла Ollama восстановить структурированный ответ без обхода валидатора (AG-005). Промежуточный live-after дал 3 failed; после исправления — 7/7, затем 15/15 на расширенном наборе (14 эпизодов реально использовали inference).
- Условия аналитики: 73 passed после исправления. Невалидный период и неподдержанная область требуют уточнения; дальнейшие смежные проверки добавлены.
- Настоящие расчёты/версии/публикация: 94 passed; 12 сквозных сценариев включённого local provider: 12 passed, с явными ограничениями what-if и метрик. Детерминированные маршруты не засчитываются как свободное LLM-решение.

## Cycle 4 — свойства и независимый lock oracle

- 60 валидаторных и 24 solver-преобразования обнаружили AG-006: перестановка исходной закреплённой бригады. Шесть детерминированных adjacent-воспроизведений failed; после сохранения frozen records и корректной UTC-нормализации oracle — 98 passed вместе с прежними core tests.
- Ошибки стенда (default limit и эквивалентные Z/+00:00) отделены от дефектов продукта. Лимит поиска не интерпретируется как infeasible.
- Оригинальные Excel повторно прочитаны локально: 217 операций/1275 marks/217 неизвестных норм; I6/I20 подтверждены, хеши не изменились. Исходники не передавались модели.
- Добавлены machine-readable capability/live корпуса и scripts/agent_redteam.py для повторяемых изолированных раундов. Начат общий --live прогон, не заменяющий частные протоколы.

Следующий шаг — разобрать любое расхождение общего прогона, сохранить проверенный checkpoint с подробным commit body и продолжить смежные проверки. Миграций/пуша/слияния в исходный проект не выполнялось.

## Cycle 5 — повторяемость, контекст и обязательные доказательства

- Первый общий прогон: 1039 passed / 4 failed за 520,47 с. Три расхождения oracle/fixture (unit timezone, неполный формат даты при корректном дне/месяце, требование LLM от детерминированного счётчика) отделены от настоящего AG-007.
- AG-007: пустой router пропускал обязательный поиск оборудования. Добавлено реальное чтение кода, 5 форматов и 503; шесть lifecycle-сценариев approval с последующей успешной независимой командой и replay. Расширенная связанная регрессия: 77 passed.
- Второй общий прогон обнаружил AG-008: агент смешивает задания/глобальные регламенты с конфигурациями конкретной единицы. Добавлена точная связка equipment_find → regulations_read; 5 проверок published/draft/empty при пустом календаре. С усиленными evidence-oracle: 76 passed.
- До каждой fault-инъекции проходит положительный контроль, после неё проверяется конкретная причина; поздний успех не скрывает старые красные протоколы.
- Следующий holdout: файлы Excel с отсутствующей нормой и инъекцией, видимое показание на синтетическом PNG и инструкция внутри изображения. Все файлы локальные/искусственные; оригинальные фото и customer XLSX не передаются модели. Начат также широкий offline Python-прогон backend+ML без фронтенда.

## Cycle 6 — файлы, точный код и полный проверяемый срез

- Holdout + регрессия live: 21/21 passed, 19 эпизодов с inference. Опорные значения XLSX/PNG подтверждены, инъекции не породили proposals/доменных изменений; fingerprint проверяет 18 таблиц. Секретные поля/headers и скрытые рассуждения в артефакты не попадают.
- Точный code lookup не должен зависеть от страницы name-search. Добавлен literal asset_code в настоящий endpoint: 30 похожих названий не скрывают точный актив; %, _, backslash, Unicode и длинный код не становятся LIKE-wildcards/обрезанным значением. Пять вариантов плюс граница 25 строк. Связанные 64 pytest проверки прошли.
- Проверка артефактов выявила забытый export описания ResultView.path. Это ошибка сопровождения изменения: часть частных pytest-прогонов была зелёной, но следующий architecture gate останавливал весь verify. Выполнен штатный --write-schema: contracts/assistant.schema.json обновлён, validate_artifacts проходит. Ранние частные числа относятся к pytest, не к целому зелёному pipeline.
- Runner записывает HEAD, manifest хешей source/test/contracts и версии пакетов, затем проверяет неизменность кода. После checkpoint исходники во время окончательного прогона не редактируются; документы можно уточнять по фактам.

- Широкая регрессия дала 1945 passed, 6 failed, 33 skipped, 5 xfailed. ENV-002 — старый assignment end-to-end изменял общий demo seed и ломал последующие optimistic-revision ожидания. Использован существующий изолированный jobs fixture, добавлен контроль неизменности seed. Порядок сценарий → runtime: 55 passed; native verify, schema/artifacts, orchestration, compile и pip прошли. Backend ради ожиданий тестов не менялся.

## Checkpoint 32c08bf — неизменные исходники

- Широкий backend/ML: **1957 passed / 33 skipped / 5 xfailed**, 539,47 с, полный native verify зелёный. Источники не менялись: source_stable=true, SHA-256 `d8632c9e7919bc38bc0bdb81c78c6fa353c37091aa6a0e2fead5c68ce3ef7665`.
- Два полных local-live раунда: каждый **1080 passed** с тем же HEAD/source hash. Это повторяемость проверенных oracle, не новое число уникальных сценариев и не доказательство истинности каждого предложения.
- Ручное чтение полных ответов выявило AG-009 несмотря на зелёный старый oracle; независимый trace-пример подтвердил AG-010. После завершения frozen-прогонов начат следующий цикл, исходники во время них не редактировались.

## Cycle 7 — не доверять даже зелёному oracle

- До исправления: 12 failed / 1 passed на 7 неизвестных/неподтверждённых norm-случаях и 5 свободных trace-значениях; resource-ID positive control прошёл.
- Добавлены readiness исходного файла до расчёта, null нормативных ячеек без сдвига quantity, источник старого файла/выбор по имени и ограничение широкой/длинной диагностики. Свободные строки trace хешируются независимо от похожести на UUID.
- Усилены реальный live unknown-norm oracle и регрессии. Связанная проверка: **63 passed / 35,01 с**, все стадии native verify прошли. Это следующий срез после 32c08bf, ожидает общего финального прогона.
