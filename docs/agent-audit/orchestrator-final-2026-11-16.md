## C. Как теперь работает поручение

1. Backend фиксирует исходное сообщение, контекст пользователя/объекта/роли и выбранную модель.
2. Модель предлагает типизированные цели. Сервер проверяет DAG, разрешённый transport, точные селекторы, требуемый источник и отсутствие подмены изменения чтением.
3. Оркестратор сохраняет план, выполняет независимые пункты и вызывает ограниченный предметный адаптер. Недоверенные документы/названия не меняют права и набор инструментов.
4. Авторизованные API возвращают факты, сервер считает и проверяет полноту. Workflow хранит собственные scoped evidence; исторический cache не заменяет свежую бизнес-проверку.
5. Запись создаёт только предложение с target/diff/hash/revision. Пользователь подтверждает конкретную карточку; сервер применяет обычные RBAC, CSRF и бизнес-правила.
6. Новый readback проверяет результат. Явный resume восстанавливает последнюю линию и уже исполненные действия, не повторяя неопределённую запись.
7. Завершение ответа закрывает транспорт. Неисполненные цели остаются `blocked`, `partial`, `awaiting_confirmation`, `uncertain` или другими незавершёнными состояниями.

Ограничение: source/identity gates не являются доказательством полной семантической декомпозиции произвольного текста. Planner может пропустить иной пункт; полный positive operation corpus ещё не выполнен. Отдельный safeguard явного manufacturer-document запроса консервативен и лексический, не заменяет общего решения этой задачи.
