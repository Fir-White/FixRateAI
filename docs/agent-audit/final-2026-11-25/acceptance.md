## Методика

Для каждого сценария отдельно сохранить ответ, трассу инструментов и модель, HTTP, карточки до подтверждения, результаты после подтверждения, SQL/ревизии и аудит. Полный успех — выполнены все замороженные ожидания; частичный не засчитывается в порог, а отказ успешен только там, где ожидался отказ. Не проверенное из-за полигона — отдельный статус, не успех и не ошибка модели.

Раздельно считать метрики по роли и классу: задача/диалог — полные успехи на оценённые случаи, точность — подтверждённые существенные утверждения на проверенные, удержание — верные продолжения на проверенные продолжения, выдумки — сценарии с существенным неподтверждённым фактом на оценённые. Успех вызовов — корректные вызовы на все попытки; успех действий сверяется с подтверждёнными HTTP+SQL. Для RBAC, записей без подтверждения и дублей указывать число нарушений и размер отрицательной выборки. Для повторяемости — успешные повторения из 30 и кейсы с тремя совпадающими исходами из 10. Задержка — end-to-end по ходу, среднее и nearest-rank p50/p95/p99 по классу; токены и стоимость — по ответам провайдера с отдельным числом вызовов без usage. API-замер реестра не входит в метрики агента.
