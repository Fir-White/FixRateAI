# Первый запуск опубликованной версии

Для установки готового продукта без Python/Node/PostgreSQL на машине пользователя предусмотрен [релизный установщик Windows/Linux](installation.md). Он проходит отдельную приёмку; developer-инструкции ниже не являются single-file installer.

Эта инструкция использует только файлы репозитория. Локальный `start-fixrate.bat`, частная инструкция заказчика, ключи, рабочая БД, фотографии и cache моделей не входят в Git. Обновление исходников не переносит эти данные на другую машину.

## Подготовка

Нужны Git, Python 3.12 и работающий Docker Desktop / Docker Engine с Compose. Для установки зависимостей и загрузки образов нужен доступ к сети. Для облачного AI нужен собственный ключ настроенного провайдера; без него нельзя обещать готовность облачных функций.

```powershell
git clone --branch dev https://github.com/krangras/FixRateAI.git
Set-Location FixRateAI
py -3.12 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
Copy-Item .env.example .env
```

Копируйте шаблон только в новой копии проекта, где `.env` ещё нет. В существующем checkout сохраняйте свои настройки. Не используйте рабочую БД для демонстрационного seed или автоматических проверок.

## Выбор AI-профиля

Для облачного запуска заполните в частном `.env` `AITUNNEL_API_KEY` и, при необходимости, адрес/имена моделей. Ключ не помещается в `VITE_*`, документацию или Git.

```powershell
.\.venv\Scripts\python.exe scripts/start_local.py --cloud-ai
```

Helper создаёт собственный постоянный Docker-проект с БД и файловым хранилищем, собирает приложение, применяет миграции и готовит демонстрационный объект. Он выводит фактический адрес и путь к частным реквизитам. Не считать заранее известным порт 8000, если он уже занят.

Подготовка локальной vision-модели и явный выбор Ollama вместо облачного AI Tunnel описаны в [руководстве по эксплуатации](runtime.md#локальная-vision-модель-для-фотоотчёта); базовый запуск без ключа AI Tunnel и без Ollama подробно разобран в разделе [первого запуска](runtime.md#первый-запуск-с-чистого-checkout). Качество модели на данных заказчика проверяется отдельно от успешного запуска сервиса.

## Проверка и вход

```powershell
.\.venv\Scripts\python.exe scripts/start_local.py --status
```

Откройте адрес, который напечатал helper. `/api/health` должен показывать готовность приложения и БД. Войдите реквизитами соответствующей роли из частного состояния стенда; в репозитории общего пароля нет. Сведения о [ролях](roles.md) помогают выбрать сценарий.

Для первого знакомства инженер начинает с реестра и подготовки планирования, исполнитель — со своих заданий, инженер приёмки — с очереди отчётов. ИИ-помощник находится в отдельном разделе; изменения требуют отдельного подтверждения и серверных прав текущего пользователя. Данные демонстрационного объекта не являются нормативами заказчика.

## Остановка и обновление

```powershell
.\.venv\Scripts\python.exe scripts/start_local.py --stop
```

Остановка helper сохраняет постоянные volumes. Перед обновлением работающей установки подготовьте резерв БД и файлов по [правилам эксплуатации](runtime.md); затем обновите исходники и запустите существующий профиль. Не удаляйте volumes и не повторяйте seed рабочей базы ради устранения ошибки запуска.

Диагностика, версии инструментов, параметры HTTPS, модельные ограничения и подробные варианты запуска: [runtime](runtime.md). Эта инструкция не подтверждает проверку каждого сочетания ОС, оборудования и провайдера на чистой машине.
