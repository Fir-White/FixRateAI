# Роли, вкладки и минимальная демонстрация

Дата: 06.11.2026. Основа — неизменённые [роли аналитика](../analysis/nastya-2026-11-04/source/docs/domain/roles.md) и [сквозной сценарий](../analysis/nastya-2026-11-04/source/docs/domain/user_flows.md). Названия вкладок ниже — привязка этих требований к интерфейсу прототипа. Четыре бизнес-роли: executive, chief_engineer, engineer, executor; в исходнике исполнитель называется Техником. Admin/dispatcher сохраняются для технического управления и совместимости, но не нужны для основного демо четырёх ролей.

## Руководитель

| Вкладка | Действия |
|---|---|
| Обзор | Сводка доступных объектов, выполнено/просрочено, SLA, трудозатраты и загрузка |
| Календарь ТО | Просмотр плана и состояния работ |
| Оборудование | Просмотр оборудования, связанных операций и истории |
| Задания | Просмотр хода выполнения, отчёта и результата приёмки |
| Прогнозы | Просмотр обоих методов, выбранной даты и объяснения |
| Отчёты | Просмотр/выгрузка доступной отчётности |
| Уведомления в шапке | Критические просрочки и эскалации |

Данные ограничены предоставленными объектами. Оперативные назначения, выполнение, утверждение регламентов и приёмка не относятся к этой роли. AI-прогнозы общего риска нагрузки из полного описания аналитика не следует отождествлять с уже вычисленной суммой плановых нормо-часов. Утверждение управленческой отчётности и стратегическое перераспределение ресурсов указаны аналитиком как выход роли; отдельный процесс их согласования здесь не заявляется реализованным.

## Главный инженер

| Вкладка | Действия |
|---|---|
| Обзор | Контроль процесса и эскалаций |
| Оборудование / Настройка обслуживания | Ведение оборудования, операций, периодичности, численности, норм, чек-листов и доказательств; утверждение полной версии |
| Календарь ТО | Проверка и утверждение месячного плана |
| Прогнозы | Запуск/просмотр сравнения, обоснованное согласование раннего некалиброванного предложения |
| Задания | Назначение; обоснованная смена начатой работы, разрешение позднего исполнения, повторное открытие |
| Контроль качества | Приёмка, доработка, проверка актов и разбор сложных работ |
| Сотрудники и смены | Доступность, квалификация и составы бригад для распределения ресурсов |
| Отчёты | История и контроль исполнения |

Позднее исполнение не переписывает обязательный договорной срок и не убирает просрочку из SLA. Неизвестные нормативы не заполняются предположениями.

## Инженер

| Вкладка | Действия |
|---|---|
| Обзор | Ежедневная очередь и просрочки |
| Календарь ТО | Расчёт по утверждённым правилам, просмотр и создание заданий |
| Прогнозы | Реальный запуск двух методов, просмотр рекомендации и решения оркестратора |
| Задания | Дозаполнение AI-черновика, выбор существующей утверждённой операции, назначение квалифицированных работников/бригады |
| Контроль качества | Анализ фото, проверка показаний/актов, принятие или мотивированный возврат |
| Оборудование / Настройка обслуживания | Чтение карточки, регламента и истории; создание/изменение оборудования и нормативов относится к главному инженеру |
| Сотрудники и смены | Проверка доступности и допусков для назначения |
| Отчёты | Выгрузка графика и нарядов XLSX |

Для 1.4 требуется два исполнителя. Не подтверждает некалиброванную раннюю AI-дату без главного инженера и не переносит обязательный срок позже регламента.

## Техник / исполнитель

| Вкладка/раздел | Действия |
|---|---|
| Мои задания | Только назначенные работы; начало выполнения, очереди в работе/на проверке/история |
| Карточка задания | Чтение регламента, норм, численности и срока; чек-лист, фактическое время, измерения, фото before/after, комментарий/акты и отправка на проверку |
| Календарь ТО | Свои работы на период |
| Оборудование | Оборудование своих заданий, связанные инструкции и история |
| Обращение внутри карточки оборудования | Фото/текст обнаруженного дефекта для проверки инженером |
| Мои смены | Просмотр своего расписания |

Не назначает других сотрудников, не меняет регламент и не принимает собственную работу. AI-заключение не переводит задание в accepted автоматически.

## Обязательный минимум прототипа: две функции

1. **Прогнозирование ТО.** Инженер открывает `Задания → карточка → Сравнить прогнозы`. Backend получает снимок оборудования, утверждённого регламента и доступной истории, рассчитывает обязательный срок и независимо вызывает AI. В `Прогнозах` видны обе даты/статусы, происхождение, итоговая дата и объяснение. Более поздняя дата не разрешается; при отказе AI остаётся явный регламентный fallback. Результат сохраняется и читается после обновления страницы.
2. **Анализ работы по фото.** Техник загружает before/after в своём задании и отправляет отчёт. Инженер открывает `Контроль качества → карточка → Анализировать фото`, подтверждает сопоставимость и получает реальный ответ модели: видимые изменения/дефекты, ограничения и непроверяемые пункты. Показания сверяются с протоколом, скрытые операции требуют ручных доказательств. Затем человек принимает или возвращает работу с причиной; фото/результат/история сохраняются.

Нужны состояния ожидания, ошибки, явного повторного запуска и недостаточных данных. Отдельные автономные экраны загрузки произвольных файлов не требуются: ранее выбран сценарий через существующие задания и приёмку. Функции работают через API, без ноутбуков и подставного production-успеха. Оба облачных инструмента проверены реальным контейнерным прогоном 05.11; это не утверждение нормативов шести customer-операций.

Полный контур исходных шести операций остаётся BLOCKED до утверждения методик, единиц норм и диапазонов. Порог 70% из исходника не используется как калиброванная уверенность модели; неполные данные явно требуют проверки человеком.

## Исправление интерфейса и допуска 06.11.2026

Обнаружено, что прошлые проверки прямых URL не выявляли пустой sidebar новых ролей. Навигация теперь использует ту же SECTION_ROLES, что router; обзор доступен инженеру, руководителю и главному инженеру. Тесты отдельно проверяют полный фактический набор ссылок четырёх ролей, независимо от router guards.

Дополнительно закрыто изменение оборудования/структуры бизнес-инженером через наследуемое право dispatcher: каталог использует явные роли с повторной проверкой членства после блокировок. Технический admin и прежний dispatcher сохраняют совместимость; engineer управляет назначениями, но каталог оборудования только читает. Новая HTTP/PostgreSQL-проверка подтверждает 403 для engineer и успешную правку главным инженером.
