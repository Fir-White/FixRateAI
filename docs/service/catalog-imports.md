# Черновики каталога СВиК: первый этап ТЗ v1.1

Реализован разбор исходного каталога, приватное сохранение источника и просмотр — основа PLN-23/28/29. Следующим этапом добавлен [редактор решений инженера](catalog-decisions.md): семантика, реальные привязки, нормы и подтверждения отдельных строк. Ниже сохранено описание исходного этапа; сегментация и публикация кадрового плана ещё не реализованы.

## Работа на сайте

В «Работы + реестр оборудования» откройте **«Каталоги регламентов СВиК»**, выберите книгу с `Лист1`, нажмите «Проверить каталог», затем явно «Сохранить каталог-черновик». Сохранённый каталог доступен после перезагрузки. Показываются разделы, виды ТО, сырая периодичность, число отметок и причины неполноты. Поиск охватывает весь каталог; UI и API выдают страницы по 25 операций. На мобильном таблица становится списком карточек.

По операции открываются исходные A:G и все 31 ячейка января. Сохраняются текст с переносами/пробелами, XML raw value, тип/стиль, формула как текст и её сохранённое значение. Отсутствующая ячейка отличается от существующей пустой. Формулы не исполняются. Год января не угадывается. Число отметок не считается числом работ, людей или смен.

Система хранит нумерованные группы, вложенность по коду и дополнительные ненумерованные заголовки. Одинаковые названия групп не объединяются. Короткий код операции относится к контексту исходной группы/каталога, а не к глобальному регламенту.

Все операции этого этапа имеют `interpretation=UNKNOWN`, `ready_for_real_plan=false`, неизвестные норму/единицу/количество и отдельные причины `NEEDS_SEMANTICS`, `NEEDS_DURATION`, `NEEDS_ASSET_BINDING`, `NEEDS_POLICY`. Типизированная подсказка периодичности помечена `confirmed=false` и не подключена к генератору. ТО2*, ТОр, day/night, included-in и многолетние частоты сохраняются отдельно. Это не расширяет незаметно действующий контракт активных ТО1/ТО2/ТО3.

## Хранение и доступ

Миграция `013_regulation_catalog_imports.sql` добавляет одну таблицу `regulation_catalog_imports`. Она хранит site/actor, время, имя, SHA-256, версию парсера, исходный XLSX как BYTEA, summary и JSONB-снимок разбора. Источник сохраняется в одной транзакции с audit; отдельные файловые копии/публичные URL не создаются. Статус таблицы ограничен `draft`.

Уникальный ключ `(site_id, source_sha256, parser_version)` предотвращает дубли при повторном и одновременном сохранении. Иной файл или версия парсера создают новый источник; прежний не переписывается. Пока нет команд изменения/удаления или подтверждения каталога. Изменения интерпретации следующего этапа должны версионироваться отдельно от исходного снимка.

Просмотр и скачивание доступны существующим управленческим ролям в текущем объекте; загрузка/сохранение — только chief_engineer/admin. Используются текущие auth/CSRF, `_edit`, блокировки пользователя/членства и audit. Другой объект получает 404; executor не получает каталог. Запросы и ответы имеют `private, no-store`. Внутренний frontend cache изолирован общим провайдером пользователя/объекта/роли.

Новые записи не создаются в `equipment`, `operation_templates`, `maintenance_rules`, `rule_equipment`, `schedule_entries`, `work_orders` или `work_assignments`. Поэтому ранее специфическое правило бригады для `1.4` к строке нового источника не применяется. Перед реализацией активных привязок его нужно перенести в контекст подтверждённого регламента, как описано в [gap analysis](planning-v1.1-gap.md).

## API

База: `/api/v1/maintenance/catalog-imports`.

| Метод и путь | Результат |
|---|---|
| `POST /preview` | Multipart `file`: разбор без записи, fingerprint пользователя/объекта/файла/парсера, summary, groups, issues, первые 25 операций |
| `POST` на базовый URL | Multipart `file`, `preview_token`: повторный разбор и валидация, новое сохранение 201 или прежний import ID с 200 |
| `GET /?offset=&limit=` | Метаданные источников, максимум 25, без BYTEA и полной сетки |
| `GET /{id}` | Summary, иерархия, заголовки, диагностика I6/I20 |
| `GET /{id}/operations?offset=&limit=&q=&group_id=&kind=` | Поиск/фильтр, до 25 summary; raw grid исключается SQL-проекцией до передачи в Python |
| `GET /{id}/operations/{row}` | Исходная строка и 31 ячейка; row ограничен допустимым Excel-диапазоном |
| `GET /{id}/source` | Приватное скачивание ровно тех байтов XLSX, которые были загружены |

Контракты ответов — `backend/app/schemas/catalog.py`, экспорт — `contracts/catalog.schema.json`. В OpenAPI опубликованы модели и ограничения параметров. SQL-проекции перечисляют нужные столбцы; источник BYTEA не попадает в списковые чтения и не добавлен в универсальный ORM reader.

Preview fingerprint не является разрешением публикации или bearer token. При сохранении заново проверяются файл, actor/site, текущая роль и структура; token имеет ограниченный hex-формат. Ошибка контекста/файла — 409; некорректный вход — 422. Произвольные URL, формулы и инструкции в ячейках не исполняются. Успешный read-only preview не сбрасывает тёплый кеш других страниц; сохранение сбрасывает, а 401/403 всегда очищают кеш независимо от режима запроса.

Пределы: 5 МБ файла, 20 МБ распакованных данных, 200 ZIP entries, 5000 строк всей книги, 200000 ячеек; каталог — до 1000 операций, до 250 групп/контекстных заголовков. Повторные имена ZIP/листов/строк/ячеек и некорректные адреса отклоняются. Принимается конкретная структура A:G, январь H:AL с днями 1–31. Полноценный редактор правил и маппинг произвольных Excel этим этапом не реализованы.

## Проверенный исходник и границы

Реальная книга №5 проверена чистым парсером и через HTTP preview на отдельном QA backend: 217 операций, ТО1=38, ТО2=46, ТО2*=5, ТО3=113, ТОр=15; 217 пустых E; 16 верхних разделов + вложенная 10.1; 1275 непустых календарных ячеек. I6 содержит текст `8+A6:S33`, I20 — формулу с сохранённым результатом 20. Источник не исправлен и не сохранён в живую БД.

Следующим этапом реализованы [решения по отдельным строкам](catalog-decisions.md) (часть PLN-24/25/26): смысл отметок, реальные активы, источник/единица нормы, бригада, делимость и версии подтверждений. Групповое применение, генератор общих обязанностей/сегментов и версии плана остаются открытыми. Сохранённый источник сам по себе не подтверждает решения.
