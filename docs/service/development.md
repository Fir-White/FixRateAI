### Что хранится в Git

Версионируются исходники и тесты, fixtures, SQL, зависимости и lock-файлы, конфиги сборки и проверок, `.env.example`, runtime-ресурсы frontend и выбранные иллюстрации документации. Схемы, оригинальные SVG и используемые изображения не исключаются общими масками.

`.gitignore` исключает локальные env и секреты, зависимости, кеши, сборки, отчёты Playwright, `reports`, `logs`, `var`, настройки редакторов и агентов, вложенные worktree и исходные экспортные пакеты `/favicons` и `/favicons-visible`. Подключённые favicon остаются в `frontend/src/assets`. `AGENTS.md` и другие локальные агентные инструкции сохраняются на диске вне индекса. Для ранее отслеживаемых артефактов удаляется только запись индекса; ignore-правило само по себе не прекращает отслеживание.

## Изменение общего контракта

1. Согласовать потребителей и формат обмена: календарь → прогнозы → решение → задание → назначение → выполнение → приёмка.
2. Обновить [DTO](../../backend/app/schemas/maintenance.py), [документный DTO](../architecture/contracts/maintenance_contracts.py), [JSON Schema](../architecture/contracts/maintenance.schema.json), примеры, SQL/DTO mapping и потребителей. Реальные команды управления описаны в schemas/management.py; зарегистрированные HTTP-маршруты — в [backend](backend.md).
3. Обновить экспорт через `docs/architecture/validate_artifacts.py --write-schema` и проверить diff. Изменение хранения оформляется следующей SQL-миграцией, без изменения применённых 001–008. Старые результаты и хеши не пересчитываются под новый контракт.
4. Проверить затронутые границы: HTTP/PostgreSQL, UI и обработку 409/422/unavailable. Для схемы нужны новая БД и upgrade с данными; для AI — origin, hash и отказы провайдера.
5. Обновить описание поведения и состояние работы в [плане](../PLAN.md). Критерии передачи — в [P0](verification.md#критерии-p0-01p0-23).

## Происхождение интеграции и обновление источников

[BRANCH_SOURCES](../BRANCH_SOURCES.json) и [BRANCH_FILE_MAP](../BRANCH_FILE_MAP.json) хранят версии источников, соответствие файлов и учтённые адаптации. Это исторические снимки, а не доказательство интеграции нового tip.

| Источник | Область |
|---|---|
| main | Предметная модель, контракты и архитектурные материалы |
| kran_dev | SQL, ORM и репозитории |
| front/mvidy, feature/frontend-kran | React SPA, форма входа и Aurora |
| new_backend | Настройки обслуживания, сотрудники, роли и регистрация |
| feat/ml-forecasting-photo-review | RF, фотоанализ и ML-контракты |
| qa/roles-contracts, docs/tests-p0 | Проверки доступа и критерии демонстрации |

При обновлении источника сравнивают последний учтённый SHA с новым tip, адаптируют изменённые пути по карте и проверяют затронутые сценарии. Принятые SQL 001–008 сохраняются; изменения схемы получают следующую миграцию. После проверки обновляют учтённый SHA и соответствие файлов в реестрах.

В задаче 02.11.2026 основной worktree `dev` обновлён `git pull --ff-only origin dev`: `720a8dd` → `6a09f3b`. Frontend-ветка осталась на прежнем HEAD. Заимствованы оформление README, навигация, разделение assets/результатов и правила игнорирования; новые результаты full-stack dev не выдаются за проверку frontend-worktree. Commit, merge и публикация требуют отдельной задачи.
