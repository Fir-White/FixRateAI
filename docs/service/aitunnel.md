# Облачный анализ через AI Tunnel

[Запуск](runtime.md) · [ML/CV](ml.md) · [API](backend.md) · [Планировщик](planning.md) · [Проверки](verification.md).

## Назначение и пользовательский сценарий

Провайдер `aitunnel` добавлен к существующим заданиям, сравнению прогнозов и инженерной приёмке. Пользователь работает в прежнем интерфейсе: диспетчер/инженер запускает прогноз, назначенный исполнитель сдаёт отчёт с парой фото, инженер запускает фотоанализ и отдельно принимает либо возвращает работу. Развёртывание облачного режима не требует Ollama, GPU и скачивания vision-весов.

По выбору владельца демо используется **qwen3.7-flash** для обоих инструментов. На 04.11.2026 публичный каталог AI Tunnel объявляет входы text/image/video; конкретный ID проверен запросом каталога. Это доступная модель провайдера, не наша оценка точности. [Каталог моделей](https://aitunnel.ru/docs/models), [передача изображений](https://aitunnel.ru/docs/images), [Chat Completions](https://aitunnel.ru/docs/api-reference).

## Настройки в .env

```dotenv
FIXRATE_CLOUD_AI=true
AITUNNEL_API_KEY=ваш_ключ_из_кабинета_AI_Tunnel
AITUNNEL_BASE_URL=https://api.aitunnel.ru/v1/
AITUNNEL_VISION_MODEL=qwen3.7-flash
AITUNNEL_FORECAST_MODEL=qwen3.7-flash
AITUNNEL_REASONING_EFFORT=none
AITUNNEL_TIMEOUT_SECONDS=90
```

Ключ — API-токен сервиса, не логин/пароль его сайта. Имеющееся имя `AI_TUNNEL_API_KEY` также поддерживается; при непустом `AITUNNEL_API_KEY` приоритет у него. Секрет не попадает в Git, Docker build context, JS, DTO и штатные логи. `repr` конфигурации скрывает ключ. Для фотографий разрешён только HTTPS `api.aitunnel.ru/v1`; редиректы и скрытые повторные запросы отключены. Секрет передаётся заголовком Authorization серверного HTTP-запроса.

Модели задаются независимо, поэтому их можно менять без переделки UI. `none` отключает reasoning и даёт короткий ответ для демонстрации. Значения low/medium/high доступны как настройка, но расходуют бюджет ответа и могут привести к усечению JSON; такой ответ будет отклонён. Приватные рассуждения не запрашиваются и не сохраняются.

## Запуск на чистой машине

Нужны Docker Desktop/Compose с Linux-контейнерами, Git и Python 3.11+. Клонировать `dev`, перейти в корень репозитория, скопировать `.env.example` в `.env` и заполнить настройки выше. Для helper достаточно установить python-dotenv; зависимости приложения устанавливаются внутри Docker:

```powershell
python -m pip install python-dotenv
python scripts/start_local.py --cloud-ai
```

Первый запуск собирает frontend/backend, поднимает PostgreSQL, применяет миграции и выполняет явный demo seed. На чистом облачном запуске CLIP-cache не требуется. По умолчанию выбирается свободный 8000/8080/8090; адрес и все роли записываются в `var/compose-local/accounts.txt`. Логин/пароль демо задаются отдельными `FIXRATE_DEMO_LOGIN` / `FIXRATE_DEMO_PASSWORD`, как описано в [runtime](runtime.md). Они не совпадают с ключом AI Tunnel.

Для уже подготовленного образа на текущем локальном стенде:

```powershell
python scripts/start_local.py --bundled-image fixrate-ai:aitunnel --cloud-ai
python scripts/start_local.py --status
```

Этот тег должен существовать локально и содержать текущий код. Для новой машины без готового образа используется первая команда без --bundled-image. [compose.cloud.yaml](../../compose.cloud.yaml) — дополнение к compose.yaml либо compose.bundled.yaml. `start_local.py` читает только разрешённые AI-настройки из .env, учитывает одноимённые переменные процесса и сохраняет приватный runtime.env.

Облачный режим заменяет профиль Ollama в том же проекте fixrate-local. Удаляется только прежний контейнер vision этого проекта; postgres_data, photos и внешний vision_models volume сохраняются. Возврат к подготовленной локальной модели: `python scripts/start_local.py --local-vision`. Ни один вариант не требует удаления настоящей БД или переписывания принятых отчётов. `--stop` останавливает проект с сохранением volumes.

## Что отправляется и что сохраняется

Фотоанализ отправляет три запроса на сопоставимую визуально проверяемую пару: независимый осмотр каждого снимка и совместное сравнение с заданием. JPEG создаётся с применением EXIF-ориентации, максимальной стороной 768 px и без исходного EXIF. Файлы передаются base64 в multipart content, публичные URL фото не создаются. Контекст включает название/инструкцию работы, пункт чек-листа, комментарий исполнителя и наблюдения. Проверки качества, одинакового ракурса/пункта и явное подтверждение сопоставимости инженером сохраняются; скрытые операции остаются not_verifiable. Неподходящие данные не превращаются в успешную проверку.

Прогноз отправляет один запрос: исходную периодичность и норму с единицей, описание оборудования/работы, принятые даты обслуживания и подтверждённую наработку, если они есть. Вычисленная дата алгоритма, адрес объекта, учётные данные и идентификаторы БД не передаются. Отсутствующие данные остаются отсутствующими. Модель может вернуть insufficient_data с null датой; попытка придумать дату без истории и наработки отклоняется.

Сервер проверяет ответ Pydantic-моделью и привязывает его к исходному снимку или замороженной попытке. Хранятся `aitunnel:<выбранная модель>`, версия промпта/метода, фактическое имя model из ответа, наблюдения/объяснение и ошибки. Облачный alias может обновляться у провайдера; он не равен закреплённому SHA весов. Два прогноза и решение сохраняются в forecast_runs/orchestration_decisions, фотоанализ — в ai_quality_checks; ручное принятие — в acceptance_reviews.

Рекомендация LLM — качественная подсказка, не обученная на заказчике модель отказов. uncertainty=unknown, calibrated=false; проценты уверенности и статистические интервалы не выдумываются. Оркестратор не переносит обязательный срок позднее регламента и не принимает более раннюю неподтверждённую LLM-дату автоматически. Фотоанализ также не закрывает задание.

## Лимиты и отказы

Транспорт ограничивает ответ 1 MiB, проверяет model, finish_reason=stop и корневой JSON-объект. Смена семейства модели, отказ, усечённый ответ, массив вместо объекта и нарушение схемы отклоняются. Для независимого осмотра лимит 800 токенов, сравнения 1400, рекомендации 1800; reasoning отключён по умолчанию. Автоматических retry нет; новый ручной анализ — новый оплачиваемый запрос и отдельная запись.

В cloud-профиле ожидание фотоанализа ограничено 120 секундами, прогноза — 100, внутренний AI Tunnel budget — 90 (настраиваемый диапазон (0,110]). Для RF сохраняется диапазон (0,5]. Общий бюджет массовой генерации календаря остаётся 8 секунд, поэтому медленный облачный ответ даёт регламентный fallback; один явный прогноз в карточке может ждать дольше. Одновременно допускаются не более двух провайдеров каждого инструмента; опоздавший worker не записывает результаты в БД.

| Ошибка | Результат |
|---|---|
| Нет ключа / 401/403 | unavailable, AITUNNEL_NOT_CONFIGURED / AITUNNEL_AUTH_FAILED |
| 402 / 429 | unavailable, AITUNNEL_QUOTA_EXCEEDED / AITUNNEL_RATE_LIMITED |
| Нет модели / 5xx / сеть | unavailable, AITUNNEL_MODEL_UNAVAILABLE / AITUNNEL_UNAVAILABLE |
| Таймаут | failed/unavailable, AITUNNEL_TIMEOUT либо внешний TIMEOUT |
| Ошибочный JSON/схема/усечение | failed, AITUNNEL_INVALID_RESPONSE |
| Неожиданная модель / редирект | failed, AITUNNEL_MODEL_MISMATCH / AITUNNEL_REDIRECT_REJECTED |
| Данных для даты нет | needs_input и null дата, либо явное отклонение выдуманной даты |

При отказе AI регламентный метод остаётся доступным; ошибка сохраняется, успешный результат RF/CLIP вместо неё не подставляется. На экране приёмки облачные отказы объясняются отдельно. Healthcheck подтверждает backend/БД, а readiness helper проверяет конфигурацию; они не расходуют токены и не гарантируют баланс/доступность внешней модели.

## Воспроизводимая проверка

```powershell
python -B scripts/verify_compose.py --cloud-ai --bundled-image fixrate-ai:aitunnel --photo-before docs/analysis/nastya-2026-11-04/source/tests/fixtures/photos/case_05_before.jpg --photo-after docs/analysis/nastya-2026-11-04/source/tests/fixtures/photos/case_05_after.jpg
```

Нужен приватный ключ и доступный облачный баланс. Проверка создаёт уникальный fixrate-qa-* с новой PostgreSQL: реальные вызовы обоих инструментов, upload/download, роли, DTO в БД, restart, отсутствие ключа и регламентный fallback, ручное принятие и история. В конце удаляются только собственные временные QA-volumes. Фото CASE-05 — synthetic_edited; прогон не доказывает реальный ремонт или точность измерений. Unit/HTTP-contract тесты в [test_aitunnel.py](../../tests/ml/test_aitunnel.py) используют явные ответы-фикстуры и не объявляются реальным инференсом.
