## 1. Базовые принципы обращения с фотоматериалами

1. **Запрет хранения приватных фото в Git:**  
   Ни при каких обстоятельствах реальные эксплуатационные фотографии объектов заказчика, содержащие виды помещений, коммуникаций или оборудования реальных зданий, **не помещаются в Git-репозиторий**.
   В Git допускаются только:
   * синтетические тестовые артефакты;
   * демонстрационные изображения со свободной открытой лицензией (CC0 / Public Domain);
   * машиночитаемые манифесты со структурами метаданных и контрольными суммами SHA-256.

2. **Изоляция локального хранилища:**  
   Локальные каталоги для сбора и тестирования реальных фото должны быть явно внесены в `.gitignore`:
   ```gitignore
   # Private customer data & raw photos
   data/customer/photos/
   data/private_storage/
   data/raw_pilot/
   *.private.jpg
   *.private.png
   ```

## 2. Процедура санитизации метаданных (Scrubbing EXIF & PII)

Перед сохранением любого фотоотчета в серверное хранилище и перед передачей изображения в модули компьютерного зрения (локальные или облачные) **обязательно выполняется процедура санитизации**:

### 2.1. Очистка EXIF-метаданных
Смартфоны и планшеты автоматически встраивают в структуру JPEG/HEIC метаданные, создающие угрозу информационной безопасности:
* **Геолокация (GPSInfo):** координаты объекта (широта, долгота, высота), позволяющие вычислить точный адрес закрытых инженерных помещений.
* **Идентификаторы оборудования:** марка, модель смартфона, серийный номер камеры, версия прошивки.
* **Временные метки устройства:** локальное время смартфона (может быть сбито или сфальсифицировано).

**Программное правило санитизации в кодовой базе FixRate AI:**
```python
from io import BytesIO
from PIL import Image

def sanitize_image_bytes(raw_bytes: bytes) -> bytes:
    """Удаляет все EXIF-метаданные, нормализует цветовую модель и возвращает чистый JPEG."""
    with Image.open(BytesIO(raw_bytes)) as img:
        # Приведение к RGB (удаление альфа-каналов и палитровых профилей)
        clean_img = Image.new("RGB", img.size)
        if img.mode == "RGB":
            clean_img.paste(img)
        else:
            clean_img.paste(img.convert("RGB"))
            
        # Сохранение без передачи блока exif
        out_buf = BytesIO()
        clean_img.save(out_buf, format="JPEG", quality=90, optimize=True)
        return out_buf.getvalue()
```

### 2.2. Защита персональных данных (PII)
* На фотоотчетах **не допускается** присутствие лиц технического персонала, жильцов или сторонних лиц. При случайном попадании человека в кадр фото бракуется либо лицо маскируется до передачи в хранилище.
* На фотографиях **не допускается** фиксация финансовых документов, пропусков, личных телефонов или записок с паролями.

## 3. Политика взаимодействия с внешними AI-провайдерами (AI Tunnel)

При использовании облачных мультимодальных моделей (через шлюз `AI Tunnel`) действуют следующие строгие правила конфиденциальности:

1. **Передача строго через HTTPS/TLS:** Запрещено использование открытых HTTP-протоколов для передачи графических данных.
2. **Только бинарный поток в оперативной памяти:** Изображения кодируются в base64 непосредственно в момент выполнения запроса. Промежуточные временные файлы на диск не сбрасываются.
3. **Запрет записи в логи:**  
   * В логи сервера и аналитические трейсы категорически **запрещается** выводить `base64`-представление фотографий, сырые байты, а также приватные URL-адреса с токенами доступа.
   * Логируются только: `execution_id`, `photo_id`, хэш `sha256`, статус ответа и диагностические коды ошибок.
4. **Обезличивание контекста в промптах:**  
   В системный промпт модели передаются только обезличенные технические параметры: тип оборудования (`pressure_gauge`), наименование регламентной операции (`Контроль параметров`) и текст проверяемого пункта чек-листа. Адрес дома, номер квартиры, наименование заказчика или ФИО инженера в запрос модели **не передаются**.

## 4. Контроль целостности и воспроизводимости (SHA-256)

1. Для каждого фотоснимка в момент приёма вычисляется канонический хэш SHA-256 от очищенных байтов изображения.
2. Этот хэш фиксируется в таблице `report_photos.original_sha256` и манифесте датасета.
3. Любое последующее изменение байтов файла делает контрольную сумму недействительной, что фиксируется автоматическими аудиторскими проверками.
