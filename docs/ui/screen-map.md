## Принципы границ

- Один маршрут — одна самостоятельная страница. Общая навигация и оболочка находятся в layout, а не в страницах.
- Список и карточка разделены: `/tasks` показывает очередь, `/tasks/:taskId` — конкретное задание. Аналогично устроены оборудование, сравнение прогнозов и приёмка.
- Панель диспетчера — обзорная страница, а не контейнер для календаря, заданий и прогнозов.
- Кабинет исполнителя имеет отдельный мобильный layout и не смешивается с рабочим местом диспетчера.
- Страницы не вычисляют нормативные сроки и права. Даты, статусы, `is_overdue`, доступность AI и решения приходят из API.
- До готовности backend используется слой `shared/api` с mock-данными `synthetic_demo`. Замена на реальный REST не требует переписывать страницы.
- Любая страница поддерживает состояния `loading`, `empty`, `error`, а для AI-сценариев — `unavailable` и `needs_input`.

## Маршруты

| Маршрут | Страница | Роли | Назначение |
|---|---|---|---|
| `/login` | Вход | все | Выбор демонстрационной роли; в production — email и пароль |
| `/` | Перенаправление | авторизованные | Переход на домашний маршрут роли |
| `/dispatcher` | Панель диспетчера | admin, dispatcher | Просрочки, нераспределённые задания, неполные данные, сводка |
| `/equipment` | Реестр оборудования | все | Поиск и фильтрация по объекту, типу, инвентарному номеру |
| `/equipment/:equipmentId` | Карточка оборудования | все | Паспорт, регламент, принятая история, наработка |
| `/calendar` | Календарь ТО | dispatcher, engineer, executor | Месячная проекция вхождений, просрочка, неполные правила |
| `/tasks` | Очередь заданий | dispatcher, engineer | Фильтры по статусу, просрочке и объекту |
| `/tasks/:taskId` | Карточка задания | dispatcher, engineer | Состав бригады, интервал, попытка, переходы |
| `/comparisons` | Сравнение прогнозов | dispatcher, engineer | Список запусков и их итоговые статусы |
| `/comparisons/:runId` | Результат сравнения | dispatcher, engineer | Snapshot, оба прогноза, решение оркестратора, причины |
| `/executor` | Кабинет исполнителя | executor | Назначенные задания и ближайшие сроки |
| `/executor/tasks/:taskId` | Выполнение задания | executor | Чек-лист, показания, фото до/после, отправка отчёта |
| `/quality` | Контроль качества | engineer | Очередь отчётов на приёмку |
| `/quality/:taskId` | Приёмка задания | engineer | Фото, AI-заключение, ограничения, принять или отклонить |
| `*` | 404 | все | Неизвестный маршрут |

## Структура frontend

```text
frontend/src/
├── app/          router, providers, guards, route constants
├── layouts/      AppShell и мобильный ExecutorLayout
├── pages/        страницы маршрутов
├── entities/     переиспользуемые таблицы и карточки домена
├── widgets/      составные блоки страниц
└── shared/       API, типы, mock-данные, session, UI-примитивы
```

Правило зависимости: `pages` → `widgets`/`entities` → `shared`. Обратные импорты запрещены. Домен не импортирует страницы.

## Контракты и данные

- Типы frontend повторяют смысл DTO `maintenance-0.1` из `backend/app/schemas`.
- API-префикс: `/api/v1/maintenance`.
- До появления FastAPI-роутеров `shared/api/maintenance.ts` возвращает fixtures.
- Происхождение данных отображается на экране: `customer` или `synthetic_demo`.
- Недоступный AI показывается как содержательный результат `unavailable`, а не как ошибка всей страницы.
- Демо-сессия хранится на клиенте только для навигации. Проверка ролей, site scope, CSRF и запрет self-accept остаются на backend.

## Параллельная разработка

| Владелец | Независимая часть |
|---|---|
| Frontend | Layout, маршруты, таблицы, карточки, состояния, mock fixtures |
| Backend API | Замена mock-функций на fetch, OpenAPI-типы, cookie/CSRF |
| Календарь | Подключение `GET /schedule` без изменения страницы |
| Прогнозы | Подключение `POST /comparisons` и `GET /comparisons/{runId}` |
| Исполнение | `GET /tasks?mine=true`, `POST /executions/{id}/photos`, submit |
| Приёмка | `POST /executions/{id}/ai-review`, `POST /tasks/{id}/review` |

## Критерии готовности каркаса

Визуальные требования и компоненты описаны в [UI-kit](ui-kit.md).

- Все маршруты открываются и переходят между собой.
- Роли видят только разрешённые разделы; прямой переход даёт экран отказа.
- Список и карточка не дублируют друг друга.
- Компоненты не содержат альтернативного расчёта сроков.
- `npm run typecheck`, `npm run build` и `npm test` выполняются без ошибок.
