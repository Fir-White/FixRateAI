## 1. Концепция агентов в FixRate AI

В системе **FixRate AI** под «агентами» понимаются специализированные программные компоненты с чётко очерченными границами ответственности, детерминированными контрактами и строгими защитными ограничениями (*Guardrails*). 

> [!IMPORTANT]
> **Принцип управляемости:** В контуре планирования и приёмки работ **нет неконтролируемого автономного LLM-цикла** (ReAct, AutoGPT и т.д.). Регламенты инженерных систем теплоснабжения и ГВС/ХВС являются критической инфраструктурой. Решение о назначении бригады и приёмке выполненных работ принимает исключительно человек (диспетчер и главный инженер соответственно).

## 3. Спецификация программных AI-агентов модуля ML

### 3.1. Агент прогнозирования срока ТО (`ForecastAgent`)

* **Назначение:** Оценка остаточного ресурса и вычисление рекомендуемой даты следующего обслуживания на основе истории наработки, предшествующих интервалов ТО и параметров оборудования.
* **Архитектура:** Чистая Python-функция с загрузчиком модели `RandomForestRegressor`.
* **Входной контракт:** [`ForecastSnapshot`](file:///home/handraqw/Projects/FixRate_AI/backend/app/schemas/maintenance.py#L148-L186).
  - Снимок является неизменяемым, детерминированным объектом.
  - Содержит вычисленный `snapshot_sha256`.
  - Включает только события, принятые до момента отсечки: `performed_at <= accepted_at <= as_of`.
* **Выходной контракт:** [`ForecastResult`](file:///home/handraqw/Projects/FixRate_AI/backend/app/schemas/maintenance.py#L206-L238) с `method="ai"`.
* **Режимы работы:**
  1. **Штатный (`status="ok"`):** Возвращает `recommended_date`, разброс деревьев `uncertainty` (`kind="tree_dispersion"`), объяснение решения (`explanation`) и предупреждения (`warnings`).
  2. **Реальные данные без истории (`status="unavailable"`):** Возвращает `recommended_date=None`, `error_code="MODEL_NOT_READY"` или `"INSUFFICIENT_HISTORY"`.
  3. **Недостаточно параметров (`status="needs_input"`):** Возвращает `recommended_date=None`, `error_code="MISSING_PARAMETERS"`.
* **Guardrails Агента Прогнозирования:**
  - **Запрет галлюцинаций:** Запрещено аппроксимировать даты при отсутствии обученной модели.
  - **Запрет подмены:** Запрещено копировать нормативную дату регламента в качестве AI-ответа.
  - **Защита от утечки будущего:** Данные после `as_of` отсекаются на уровне валидации Pydantic.

### 3.2. Агент анализа фотоотчётов («До/После») (`PhotoReviewAgent`)

* **Назначение:** Объективная визуальная оценка изменений состояния оборудования при выполнении регламентных работ (в пилоте — операция 1.4: «Чистка всех узлов и агрегатов системы»).
* **Архитектура:** Локальная мультимодальная модель `CLIP ViT-B/32` (`openai/clip-vit-base-patch32` через `transformers`) + предварительный фильтр резкости и контрастности на `Pillow`/`NumPy`.
* **Входной контракт:** [`PhotoReviewRequest`](file:///home/handraqw/Projects/FixRate_AI/backend/app/schemas/maintenance.py#L386-L406).
  - Принимает только замороженный отчет в статусе `submitted`.
  - Фотографии сгруппированы по парам `before` / `after` для каждого `checklist_item_id`.
* **Выходной контракт:** [`PhotoReviewResult`](file:///home/handraqw/Projects/FixRate_AI/backend/app/schemas/maintenance.py#L423-L436) с массивом заключений [`ItemPhotoReview`](file:///home/handraqw/Projects/FixRate_AI/backend/app/schemas/maintenance.py#L414-L422).
* **Возможные вердикты по пункту чек-листа:**
  - `visible_change` — на фото зафиксировано подтверждённое улучшение состояния (рост сходства с текстовым классом чистой поверхности выше установленного порога).
  - `no_visible_change` — статистически значимых изменений не обнаружено (разница скоров ниже порога чувствительности).
  - `uncertain` — фотографии не позволяют сделать вывод (размытие, недостаточная освещённость, несовпадающий ракурс `view_key`).
  - `not_verifiable` — операция не подлежит визуальной проверке (скрытые работы, инструментальные замеры).
* **Guardrails Агента Фотоанализа:**
  - **Запрет автоматической приёмки:** Агент не выставляет финальный статус наряда. Решение принимает инженер.
  - **Изоляция скрытых операций:** Пункты 1.5 («Проверка точности приборов») и 1.6 («Выпуск воздуха из системы») **принудительно помечаются `not_verifiable`**, даже если пользователь прикрепил фотографию манометра или клапана. Фото прибора не доказывает калибровку, а фото крана не доказывает отсутствие завоздушивания.
  - **Защита от подделок:** Проверка идентичности хешей SHA-256. Одинаковые фото «до» и «после» помечаются `uncertain` с предупреждением `IDENTICAL_PHOTOS_DETECTED`.

### 3.3. Агент-Оркестратор (`OrchestratorAgent`)

* **Владелец модуля:** Артём (совместно с Мухаммадом и Яной).
* **Назначение:** Сравнение двух независимых прогнозов (`method="algorithmic"` и `method="ai"`), защита нормативных сроков и принятие решения о дате постановки в план.
* **Входной контракт:** `ForecastSnapshot`, `ForecastResult(algorithmic)`, `ForecastResult(ai)`.
* **Выходной контракт:** [`OrchestrationDecision`](file:///home/handraqw/Projects/FixRate_AI/backend/app/schemas/maintenance.py#L240-L258).
* **Политика оркестрации (`policy_version="v1.0"`):**
  1. **Проверка идентичности снимка:** Если хеши `snapshot_sha256` у двух результатов не совпадают $\to$ аварийный отказ.
  2. **Защита дедлайна:** Если $Date_{AI} > MandatoryDueDate$ $\to$ итоговая дата ограничивается дедлайном, выставляется статус `fallback` с кодом `AI_AFTER_DEADLINE`.
  3. **Защита окна раннего выполнения:** Если $Date_{AI} < EarliestDate$ $\to$ дата сдвигается на границу `earliest_date` с кодом `AI_BEFORE_WINDOW`.
  4. **Выбор оптимального срока:** Если оба прогноза валидны и лежат внутри окна $[EarliestDate, MandatoryDueDate]$, оркестратор выбирает более раннюю дату: $\min(Date_{algo}, Date_{AI})$ для предотвращения аварийного износа.
  5. **Отказ AI:** Если AI вернул `unavailable` / `failed` $\to$ статус `fallback` с алгоритмической датой.

## 4. Протокол взаимодействия агентов

```
[Пользователь / Таймер]
         │
         ▼
[Backend: Яна] ─────────► Собирает неизменяемый ForecastSnapshot
         │
         ├───► [Алгоритмический планировщик: Артём] ───► ForecastResult(algorithmic)
         │
         └───► [AI-Агент прогноза: Мухаммад] ──────────► ForecastResult(ai)
                                                                 │
                                                                 ▼
[Оркестратор: Артём] ◄───────────────────────────────────────────┘
         │
         ▼
 Формирует OrchestrationDecision (selected / fallback / manual_review)
         │
         ▼
[Backend: Яна] ─────────► Атомарно сохраняет Snapshot, 2 Result, 1 Decision в PostgreSQL
```
