# Работа с FixRateAI

Краткое описание проекта и вход для разработчика — корневой [README.md](README.md). Подробная документация поддерживается в единственном комплекте [docs/INDEX.md](docs/INDEX.md).
Прочитайте [архитектуру](docs/ARCHITECTURE.md), затем только нужный узел из [service](docs/service/INDEX.md), [план](docs/PLAN.md) и связанные [ADR](docs/decisions/INDEX.md). Не загружайте все документы подряд.

Текущий продукт планирует обслуживание оборудования и работу людей. Архивный оценщик повреждений/стоимости — другой проект; legacy не изменять. Факты сверять с кодом, SQL, контрактами и тестами. Непроверенные гипотезы не объявлять реализацией, старые результаты — новым прогоном.

Поддерживать один README в корне; не создавать README, журналы, копии архитектуры или инструкции в модулях. Все тесты и fixtures хранить в корневом tests, рабочий env-файл — в корневом .env (не публиковать). Одну подробную тему поддерживать в одном разделе docs, обновляя индексы и связи. Машинные схемы, fixtures, исходный Excel, диаграммы и результаты запусков не являются вторым комплектом документации.
