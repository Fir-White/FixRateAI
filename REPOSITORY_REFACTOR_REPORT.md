# Подготовка FixRate AI к демонстрационному выпуску

Статус: **локальный демонстрационный кандидат проверен; внешний релиз не допущен**. Проектный практикум УрФУ; не промышленная приёмка. Ветка `feature/release-readiness-20261127`, отдельное рабочее дерево. База `ea97765` плюс точно перенесённый индекс редактора ТО (35 файлов, SHA‑256 снимка `f43e5c2321bf6d7ec543b14814d782c2309ace042f8386a211a3e447a3eb09a2`). Предыдущее рабочее дерево, другие ветки и действующие стенды не изменены.

## Исходное состояние

- React/Vite в `frontend/`; FastAPI и ассистент в `backend/app/` и `backend/app/assistant/`; PostgreSQL и неизменяемые миграции в `database/`; `ml_service/` — отдельный код, который FastAPI импортирует локально, а не обязательный сетевой сервис. Контракты, тесты, учебные fixtures и документация уже отделены. Перемещение runtime-кода не требуется.
- `compose.yaml` — сборка из исходников; `deploy/` уже содержит pinned образы, Caddy, PostgreSQL, мигратор, процесс API и worker, шаблоны установки и backup/restore. GitHub Actions собирает и проверяет эти же образы. Разрыв: релизный Compose по умолчанию выбирал v2, а исходный — v4; job публикации допускал обычный push в `main`; отдельного компактного Quick Start ZIP не было.
- Исходная архитектура v4 уже работает с типизированным Tool Calling; подписанные действия и диалоги привязаны к фактическим user/site/role. Различия между `engineer` и `chief_engineer` проходят через backend, UI и реестр. Нельзя устранять их переименованием роли или копированием максимальных прав.
- База редактора: 3307 Python-тестов прошли, 65 пропусков и 1 ожидаемое падение; 672 Vitest; 2 редакторских и 10 регрессионных Chrome E2E. На новом рабочем дереве повторены production-сборка, 1849 локальных ссылок и контракты (195 операций, 774 ролевых ячейки). Исходный Compose и Cloud override разобрались; Ollama ожидаемо требует pin модели. Docker Compose CLI установлен, Docker Engine недоступен; Docker Desktop не запускался во избежание запуска прежних стендов.

### Правила выполнения

Не изменять v4 как архитектуру, миграции, реальные данные, внешний вид приложения или чужие изменения. Для расширения доступа использовать явные предметные разрешения, а не наследование всех привилегий руководителя/администратора. В Preview/Apply и в отчётах сохранить ревизии, серверные проверки и пользовательское подтверждение. Офлайн-сценарии не заменяют живую оценку ИИ. На этапе подготовки публичный выпуск, развёртывание и платный API запрещены; последующий push исходников выполняется отдельно по разрешению владельца.

### Проверки кандидата

- Подготовлен локальный **тестовый**, неустанавливаемый из публичного реестра комплект `FixRateAI-QuickStart-0.1.0.zip` (`channel=test`, незакоммиченный источник, образы `local-*:test`). Внешние и внутренние SHA‑256 проверены, `-Action verify` и `bash … verify` прошли. Повторная упаковка с тем же входом дала побайтово одинаковые пять файлов. Миграционный head в манифесте `030_work_consumptions.sql`; SQL-файлы не менялись. CI включает чистый запуск распакованного ZIP до `/setup` и входа, но эта проверка не выполнена без Docker Engine.
- Chrome на production-сборке и одноразовой БД проверил фактические сессии, паритет инженерных инструментов, назначение и обе фазы доказательств. Для снимков чата проверялся фактический ответ `qwen3.5:4b-q4_K_M`, вызвавший инструмент чтения, без записей и без обращения к платному API. Не засчитывается за живую приёмку v4 или измерение VLM.
- В API-повторе проверены реальные `403` для исключений, `409` для просроченной приёмки без отдельного основания и повторного решения, сохранение фактической роли и ровно одной записи приёмки. Для MVP нет отдельного уполномоченного согласователя; выпуск не считается выполнением этого требования заказчика.
- Независимое ревью обнаружило пять расхождений. Действующий регламент защищён от замены черновиком, черновик каталога доступен обоим инженерам, штатная приёмка и правка черновика доступны как типизированные предложения v4, чистый старт ZIP добавлен в smoke. Подтверждение прогноза перечитывает наряд, календарное вхождение, роль и хеш исходных данных под блокировками. Тест реальной конкурентной правки воспроизвёл прежнее `200`, после исправления получает `409` без аудита подтверждения. В тестах карточек выбор инструмента задаёт тестовый provider; API, PostgreSQL, подтверждение, повтор и чужой `404` реальны. Снимки чата не используют тестовый provider.
- Первые широкие прогоны выявили устаревшую матрицу, несовпадение `compose.bundled.yaml` с основным Compose и коллизию порта локального раннера. Матрица обновлена генератором, bundled синхронизирован; раннер проверяет путь своего временного кластера до создания БД. Повтор контрактов/пакета/модульного Compose: **30 passed**. В контракте 195 операций и 774 ячейки базовой матрицы; регистрация не засчитывается за успешный ответ.

Состояние после записи сверяется с сервером, а не с текстом чата.

У каталога межполевые условия проверяются после слияния частичной правки, а сохранённые календарные значения сравниваются вместе с серверными defaults. ### Ворота выпуска

- Docker Engine отсутствует (`dockerDesktopLinuxEngine`), поэтому сборка образов, старт, HTTPS, container smoke, upgrade и restore не подтверждены здесь. Проверки нативной БД, архива и синтаксиса Compose их не заменяют.
- Живая облачная приёмка v4 остаётся `NO-GO`; платных вызовов в этой работе не было. Для публичного облака нужны проверяемый серверный лимит расхода/частоты, допуск владельца и отдельный живой протокол.
- Публикация требует защищённого тега из `main`, ручного запуска и одобрения `release` без self-review и admin bypass. Четыре недопустимых запуска и три небезопасных варианта настройки среды отклонены в локальной проверке без GitHub/Docker. Реальная настройка релизной среды, сборка в GitHub Actions, GHCR и публикация Releases не проверены на площадке; развёртывания не было. Сохранение исходников в `dev` не открывает эти ворота.
